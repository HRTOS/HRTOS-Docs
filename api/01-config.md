# 系统配置模块

## 模块简介

系统配置模块定义 HRTOS 的基本数据类型、系统配置参数、任务状态、等待类型以及内核核心数据结构，为任务管理、调度、资源管理和消息队列等模块提供基础定义。

本模块主要包括：

- 基本数据类型与常用宏定义
- 系统时间及任务数量配置
- 调度级别定义
- 任务状态、等待类型与唤醒标志
- 任务控制块（TCB）
- 统一资源对象与消息队列控制块
- 内核对象数组的外部声明
- 临界区操作宏与中断退出接口

系统配置参数会影响内核对象数量、数据结构布局及相关资源占用。修改配置时，应结合内核实现、目标芯片资源和应用需求进行评估。

## 基本数据类型

### 类型定义

| 类型定义 | 原类型 | 说明 |
|---|---|---|
| `u8` | `unsigned char` | 无符号字符型 |
| `u16` | `unsigned int` | 无符号整型 |
| `u32` | `unsigned long` | 无符号长整型 |
| `f32` | `float` | 单精度浮点类型 |
| `f64` | `double` | 双精度浮点类型 |
| `NULL` | `0` | 空指针常量定义 |

以上类型通过预处理宏定义实现，而不是独立的类型别名声明。实际位宽及浮点类型的具体表示应以目标编译器为准。

本头文件直接将 `NULL` 定义为 `0`，使用时应注意与其他头文件中的同名定义保持兼容。

## 系统配置参数

### 时间配置

| 配置宏 | 默认值 | 说明 |
|---|---:|---|
| `OS_TIME_ONCE_DEFAULT` | `5` | 默认时间片数量 |
| `OS_TIME_T0` | `10000` | 时间片相关时基配置，源码注释为单个时间片长度 |

`OS_TIME_T0` 的具体计时单位、定时器配置方式和实际时间长度，需要结合定时器初始化及时间管理源码确认，不能仅根据宏值直接推断实际毫秒数。

### 任务数量配置

| 配置宏 | 默认值 | 说明 |
|---|---:|---|
| `OS_PROCESS_MAX` | `16` | 标准任务数量上限 |
| `OS_FAST_TASK_MAX` | `2` | 高速任务数量上限 |
| `OS_MAX_TASK` | `OS_PROCESS_MAX` | 标准任务数量配置的别名 |

标准任务与高速任务的具体存储方式、任务 ID 分配规则及调度关系，应结合任务管理和上下文切换源码确认。

### 调度级别

`OS_SCHED_LEVEL_MAX` 的默认值为 `10`。

| 级别 | 类型 | 说明 |
|---|---|---|
| 0–7 | 普通任务优先级 | 普通任务使用的优先级范围 |
| 8 | 高优先级任务 | 源码注释定义的高优先级任务级别 |
| 9 | 中断级 | 中断处理相关级别 |
| 10 | 中断嵌套级 | 中断嵌套处理相关级别 |

以上划分来自配置头文件中的注释。具体调度行为、中断嵌套条件及不同级别之间的切换规则，应以调度器和中断处理源码为准。

## 任务状态

HRTOS 使用以下宏定义表示任务状态。

| 宏定义 | 值 | 说明 |
|---|---:|---|
| `READY` | `0` | 就绪态 |
| `WAIT` | `1` | 等待态 |
| `RUNNING` | `2` | 运行态 |
| `SUSPEND` | `3` | 挂起态 |
| `DEAD` | `4` | 删除态 |

这些宏用于标识任务状态。各状态的进入条件、退出条件及状态转换规则，需要结合任务管理实现理解。

## 等待类型与唤醒标志

### 等待类型

| 宏定义 | 值 | 说明 |
|---|---:|---|
| `WAIT_NONE` | `0` | 无等待 |
| `WAIT_DELAY` | `1` | 延时等待 |
| `WAIT_SEM` | `2` | 信号量等待 |
| `WAIT_MUTEX` | `3` | 互斥锁等待 |
| `WAIT_MSG_SEND` | `4` | 消息队列发送等待，源码注释对应队列满的情况 |
| `WAIT_MSG_RECV` | `5` | 消息队列接收等待，源码注释对应队列空的情况 |
| `WAIT_EVENT` | `6` | 事件等待 |
| `WAIT_MAILBOX` | `7` | 邮箱等待 |

等待类型用于标识任务当前等待的类别。源码注释明确指出，一个任务在同一时刻只允许存在一种等待源。

具体的阻塞、超时和唤醒流程，应以对应内核模块的实现为准。

### 唤醒标志

| 宏定义 | 值 | 说明 |

| `WAIT_SIGNAL` | `2` | 信号唤醒 |

这两个宏用于区分等待结束的原因。其设置时机、清除时机及对 API 返回值的影响，需要结合等待管理和对象操作代码确认。

### 无效 ID

| 宏定义 | 值 | 说明 |
|---|---:|---|
| `OS_INVALID_ID` | `0xFF` | 无效 ID 标识 |

该宏提供统一的无效 ID 常量，具体适用范围应以各接口的实现为准。

## 任务控制块 OS_TCB

任务控制块用于保存任务的优先级、运行状态及等待信息。等待信息直接存储在任务控制块中。

### 结构定义

```c
typedef struct
{
    u8 base_prio;      /* 静态优先级 */
    u8 cur_prio;       /* 动态优先级 */
    u8 state;          /* 任务状态 */
    u8 wait_type;      /* 等待类型 */
    u8 wait_flag;      /* 等待结果 */
    u8 wait_obj;       /* 等待对象 ID */
    u16 wait_tick;     /* 超时等待 tick */
} OS_TCB;
```

### 成员说明

| 成员 | 类型 | 说明 |
|---|---|---|
| `base_prio` | `u8` | 静态优先级 |
| `cur_prio` | `u8` | 动态优先级 |
| `state` | `u8` | 任务状态 |
| `wait_type` | `u8` | 当前等待类型 |
| `wait_flag` | `u8` | 等待结果标志 |
| `wait_obj` | `u8` | 等待对象 ID |
| `wait_tick` | `u16` | 超时等待 tick |

`base_prio` 和 `cur_prio` 分别记录静态优先级与动态优先级。等待相关成员共同记录任务的等待类别、等待对象、等待结果及超时信息。

动态优先级的调整策略、等待对象 ID 的编码方式，以及 `wait_tick` 的更新机制，应结合相关内核实现进一步说明。

## 统一资源对象 OS_RESOURCE

HRTOS 使用统一资源对象结构保存资源值、拥有者信息和等待队列信息。

### 结构定义

```c
typedef struct
{
    u8 value;           /* 资源值 */
    u8 owner;           /* 当前拥有者 */
    u8 wait_cnt;        /* 当前等待任务数量 */
    u16 wait_mask;      /* 位图等待队列 */
    u8 pending_signal;  /* ISR 中断计数 */
} OS_RESOURCE;
```

### 成员说明

| 成员 | 类型 | 说明 |
|---|---|---|
| `value` | `u8` | 资源值 |
| `owner` | `u8` | 当前拥有者，仅互斥锁使用 |
| `wait_cnt` | `u8` | 当前等待任务数量 |
| `wait_mask` | `u16` | 位图形式的等待队列 |
| `pending_signal` | `u8` | 源码注释注明用于 ISR 中断计数 |

`wait_mask` 使用位图记录等待任务，bit0 对应 task0，bit1 对应 task1，以此类推，bit15 对应 task15。

该位图的定义覆盖标准任务的 16 个编号位置。实际等待任务的选择顺序、等待计数维护方式，以及 `pending_signal` 的累积与消费规则，应以资源管理和中断相关源码为准。

源码注释将信号量、互斥锁、事件及消息等待相关对象列入统一资源对象的使用说明。各类对象的具体操作流程与适用范围，需要结合相应接口实现确认。

## 消息队列控制块 os_msgq_t

消息队列控制块保存消息缓冲区指针、队列容量相关信息及读写状态。

### 结构定义

```c
typedef struct
{
    u8 *buf;       /* 缓冲区指针 */
    u8 _size;      /* 队列容量相关字段 */
    u8 head;       /* 写指针，生产者 */
    u8 tail;       /* 读指针，消费者 */
    u8 count;      /* 当前消息数量 */
} os_msgq_t;
```

### 成员说明

| 成员 | 类型 | 说明 |
|---|---|---|
| `buf` | `u8 *` | 消息缓冲区指针 |
| `_size` | `u8` | 队列容量相关字段 |
| `head` | `u8` | 写指针，生产者使用 |
| `tail` | `u8` | 读指针，消费者使用 |
| `count` | `u8` | 当前消息数量 |

从结构定义可以确认，该控制块保存消息缓冲区及队列读写状态。消息格式、缓冲区分配方式、容量边界、指针回绕规则，以及队列满或空时的具体行为，应结合消息队列实现说明。

## 资源数量配置

| 配置宏 | 默认值 | 说明 |
|---|---:|---|
| `OS_RESOURCE_MAX` | `6` | 统一资源对象数组的元素数量 |
| `OS_MSGQ_MAX` | `3` | 消息队列对象数组的元素数量 |

以上为当前配置头文件中的定义。修改这些参数时，应同步检查数组定义、对象创建接口、访问边界及目标芯片的可用内存。

增加对象数量会增加相应的数据存储需求，实际内存增量取决于结构体布局、编译器实现及存储空间限定。

声明统一资源对象数组，元素数量由 `OS_RESOURCE_MAX` 决定。

### 消息队列对象数组

声明消息队列控制块数组，元素数量由 `OS_MSGQ_MAX` 决定。

以上均为外部声明，表示相应对象在其他编译单元中定义。本头文件声明了对象的类型、名称及数组长度，并未在此处定义数组本体。

## 临界区与中断退出接口

### 临界区操作宏

```c
#define OS_ENTER_CRITICAL() \
    do { os_enter_critical(); } while (0)

#define OS_EXIT_CRITICAL() \
    do { os_exit_critical(); } while (0)
```

`OS_ENTER_CRITICAL()` 和 `OS_EXIT_CRITICAL()` 分别调用 `os_enter_critical()` 与 `os_exit_critical()`，用于封装临界区进入和退出操作。

临界区的具体保护方式、嵌套支持、原中断状态的保存与恢复规则，应以对应函数的实现为准。使用时应遵守内核规定的调用及配对规则。

### 中断退出接口

```c
extern void os_interrupt_exit();
```

该声明提供 `os_interrupt_exit` 函数的外部接口。其适用条件、调用约束和中断退出行为应参照中断管理模块的说明。

## 配置修改注意事项

### 任务数量

修改 `OS_PROCESS_MAX` 或 `OS_FAST_TASK_MAX` 前，应核实任务创建接口、任务 ID 分配、任务控制块存储及上下文切换逻辑是否支持对应配置。

标准任务与高速任务可能采用不同的存储或调度处理方式，不能仅根据两个数量宏推断任务总数或所有任务的内存布局。

### 时间参数

修改 `OS_TIME_ONCE_DEFAULT` 或 `OS_TIME_T0` 前，应核实时间片初始化、定时器配置、计时单位及调度触发机制。

时间配置可能影响任务调度频率和时间相关 API 的行为，但实际影响取决于内核实现，不能只根据宏值判断系统响应时间或实时性。

### 资源数量

修改 `OS_RESOURCE_MAX` 或 `OS_MSGQ_MAX` 前，应检查对应数组定义、对象创建接口、访问边界及目标芯片可用的内部和外部 RAM。

配置的对象数量上限不代表应用程序可以无条件创建相同数量的对象，实际可用数量还受到对象管理实现和运行时约束的影响。

### 配置与实现一致性

修改配置后，应重新编译并检查相关模块，确保宏定义、数组长度、任务管理逻辑和对象访问范围保持一致。

对于优先级、中断嵌套、超时等待、资源唤醒和消息队列行为等机制性问题，应以对应实现源码和专项文档为准，避免仅凭配置定义作出结论。
