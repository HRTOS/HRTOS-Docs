# 任务管理模块

## 模块简介

HRTOS 任务管理模块提供任务状态查询、挂起与恢复、主动让出 CPU、任务退出与删除、优先级调整、当前任务识别，以及任务注册配置锁管理等功能。

模块通过任务编号访问标准任务和高速任务，并结合调度状态、任务运行标志、任务上下文及系统调度控制变量完成任务管理操作。

任务管理接口并不都直接完成任务切换。部分接口负责修改任务状态或调度标志，并通过触发 Timer0 中断请求内核执行后续调度；任务删除也采用请求标记与后续清理相结合的方式。

## 设计目标

- 提供统一的任务状态查询与有效性检查接口。
- 支持任务挂起、恢复、主动让出 CPU 和退出。
- 支持运行期间修改任务优先级，并在特定条件下进行标准任务与高速任务之间的转换。
- 提供指定下一次运行任务的调度控制接口。
- 提供当前任务编号查询。
- 管理任务注册配置锁状态。

## 使用场景

- 查询任务是否已注册以及当前调度状态。
- 暂停某个任务，并在条件满足后恢复该任务。
- 让当前任务主动请求调度。
- 在任务执行过程中退出当前任务，或请求删除指定任务。
- 根据系统运行需要调整任务优先级。
- 在特定调度控制场景下指定下一次运行的任务。
- 查询或控制系统任务注册配置锁。

## 任务编号与任务类型

本模块使用任务编号区分标准任务和高速任务。根据当前实现中的编号判断方式，任务编号范围由 `OS_PROCESS_MAX` 和 `OS_PROCESS_MAX + 1` 确定。

| 任务类型 | 编号范围 | 管理方式 |
|---|---|---|
| 标准任务 | `0` 至 `OS_PROCESS_MAX - 1` | 通过 `OS_PROCESS_OK[]`、`OS_TASK[]` 等状态信息管理 |
| 高速任务 A | `OS_PROCESS_MAX` | 通过高速任务 A 对应的运行标志和上下文管理 |
| 高速任务 B | `OS_PROCESS_MAX + 1` | 通过高速任务 B 对应的运行标志和上下文管理 |

标准任务与高速任务使用不同的状态管理路径，因此部分接口对两种任务类型的处理方式并不完全相同。

**注意：** 任务编号是否有效、任务是否已注册、任务是否处于就绪状态，是不同的判断条件。使用接口时应结合具体返回值及任务类型进行判断。

## 任务状态说明

`os_task_get_state()` 返回以下状态编码：

| 返回值 | 含义 | 说明 |
|---|---|---|
| `0` | 未注册或已删除 | 标准任务的注册状态为零，或高速任务对应的上下文标记为零 |
| `1` | 当前运行任务 | 任务编号与 `OS_CURRENT_TASK` 相同 |
| `2` | 就绪状态 | 标准任务的就绪位有效，或高速任务对应的运行标志有效 |
| `3` | 挂起状态 | 任务仍被识别为已注册，但当前不满足对应的就绪判断 |
| `4` | 前一任务 | 任务编号与 `OS_PREV_TASK` 相同 |
| `-1` | 编号无效 | 任务编号超出接口允许范围 |

上述状态是查询函数根据内核变量计算得出的结果，不应简单视为所有任务共享的独立状态字段。

特别是，返回值 `4` 表示任务编号与 `OS_PREV_TASK` 相同，并不表示任务发生了超时。返回值 `3` 也不一定能区分所有可能的等待原因。具体状态判断顺序以当前实现为准。

## 优先级说明

标准任务的自然优先级范围为 `0` 至 `7`，高速任务使用固定的优先级编码 `8`。

| 优先级 | 适用任务 | 说明 |
|---|---|---|
| `0` 至 `7` | 标准任务 | 通过 `OS_PROCESS_OK[]` 中的优先级位保存 |
| `8` | 高速任务 | 由高速任务管理机制处理 |

`os_task_set_priority()` 可以在标准优先级范围内修改标准任务优先级，也可以在满足条件时将任务从标准任务类型转换为高速任务类型，或从高速任务类型转换为标准任务类型。

标准任务与高速任务之间的转换涉及任务编号、堆栈指针和上下文数据的迁移，因此不能将其简单理解为修改一个优先级字段。

## 宏定义

本模块没有单独定义公开宏。实现中使用的任务数量、任务状态、优先级上限、调度标志和上下文相关标识符由 HRTOS 内核及配置模块提供。

## API 详细说明

### os_task_suspend

**函数原型**

```c
char os_task_suspend(unsigned char id);
```

**参数说明**

| 参数 | 类型 | 说明 |
|---|---|---|
| `id` | `unsigned char` | 要挂起的任务编号 |

**返回值**

- `1`：函数完成挂起标志设置并请求调度。
- `-1`：任务编号超出允许范围。

**功能说明**

该函数根据任务类型修改相应的就绪或运行标志。

对于标准任务，函数通过清除 `OS_PROCESS_OK[id]` 的最低位，将其从标准任务的就绪判断中移除。

对于高速任务，函数根据任务编号清除对应高速任务的运行标志。

函数随后设置 `OS_SCHED_REASON` 并触发 Timer0 中断，请求系统重新进行调度。

**使用示例**

```c
char result;

result = os_task_suspend(1);

if (result == 1)
{
    /* 已提交挂起操作 */
}
```

**注意事项**

- 当前实现没有检查任务是否已注册，也没有排除任务编号 `0`。
- 函数没有在内部使用 `EA = 0` 保护状态修改。
- 返回 `1` 表示相关标志已修改并触发调度请求，不等同于目标任务的所有资源已经完成处理。
- 如果需要挂起当前任务，建议使用 `os_task_suspend_self()`，以明确表达操作对象。

### os_task_get_state

**函数原型**

```c
char os_task_get_state(unsigned char id);
```

**参数说明**

| 参数 | 类型 | 说明 |
|---|---|---|
| `id` | `unsigned char` | 要查询的任务编号 |

**返回值**

- `0`：未注册或已删除。
- `1`：当前运行任务。
- `2`：就绪状态。
- `3`：挂起状态。
- `4`：前一任务。
- `-1`：任务编号超出允许范围。

**功能说明**

函数分别针对标准任务和高速任务进行判断。

对于标准任务，判断顺序为：

- 如果 `OS_PROCESS_OK[id] == 0`，返回 `0`。
- 如果任务编号等于 `OS_CURRENT_TASK`，返回 `1`。
- 如果任务编号等于 `OS_PREV_TASK`，返回 `4`。
- 如果 `OS_PROCESS_OK[id]` 的最低位为 `1`，返回 `2`。
- 其他情况返回 `3`。

对于高速任务，函数优先检查当前任务编号和前一任务编号，然后根据高速任务上下文标记及对应运行标志返回状态。

**使用示例**

```c
char state;

state = os_task_get_state(1);

if (state == 2)
{
    /* 查询结果为就绪状态 */
}
```

**注意事项**

- 该函数是基于内核状态变量进行分类，并非所有状态都直接来自 `OS_TASK[id].state`。
- 返回值 `4` 是前一任务标识，不是超时状态。
- 判断结果受当前任务编号、前一任务编号和任务类型影响。
- 需要判断任务是否注册时，应结合 `os_task_is_valid()` 使用，而不是只依赖状态值。

### os_task_set_next

**函数原型**

```c
char os_task_set_next(unsigned char id);
```

**参数说明**

| 参数 | 类型 | 说明 |
|---|---|---|
| `id` | `unsigned char` | 指定的下一次调度目标编号 |

**返回值**

- `1`：成功设置下一次调度目标。
- `-1`：编号无效、目标任务不满足就绪判断，或当前调度请求槽位已被占用。

**功能说明**

该函数用于指定下一次调度目标，而不是直接执行完整的任务上下文切换。

函数首先检查任务编号范围及目标任务的就绪条件。标准任务通过 `OS_PROCESS_OK[id]` 的最低位判断；高速任务则分别检查对应的高速任务运行标志。

如果 `OS_JINCHENG_CUNCHU` 为 `0`，函数会：

- 将 `OS_JINCHENG_CUNCHU` 设置为 `1`。
- 将当前任务编号保存到 `OS_PREV_TASK`。
- 将目标编号写入 `OS_CURRENT_TASK`。
- 设置 `OS_SCHED_REASON`。
- 触发 Timer0 中断。

如果当前调度请求槽位已被占用，函数返回 `-1`。

**使用示例**

```c
char result;

result = os_task_set_next(1);

if (result == 1)
{
    /* 下一次调度目标已设置 */
}
```

**注意事项**

- 该接口会改变内核记录的当前任务和前一任务信息，并影响后续调度路径，应谨慎使用。
- 目标任务必须满足对应的就绪判断。
- 当前实现没有在该函数中检查 `OS_JINCHENG_CUNCHU` 之外的其他调度冲突条件。
- 不应将返回 `1` 理解为目标任务已经开始执行；函数只是设置调度目标并请求调度。
- 该接口不适合代替常规的任务挂起、恢复或优先级调度机制。

### os_task_resume

**函数原型**

```c
char os_task_resume(unsigned char id);
```

**参数说明**

| 参数 | 类型 | 说明 |
|---|---|---|
| `id` | `unsigned char` | 要恢复的任务编号 |

**返回值**

- `1`：恢复标志设置成功。
- `-1`：编号无效，或目标任务不存在。

**功能说明**

该函数根据任务类型恢复相应的就绪或运行标志。

对于标准任务，如果 `OS_PROCESS_OK[id] == 0`，函数返回 `-1`；否则设置最低位，使任务重新满足标准任务的就绪判断。

对于高速任务，函数先检查对应的 `OS_KUAI_SP[]` 是否为零。如果为零，则认为任务不存在并返回 `-1`；否则设置对应的高速任务运行标志。

成功后，函数设置 `OS_SCHED_REASON` 并触发 Timer0 中断。

**使用示例**

```c
char result;

result = os_task_resume(1);

if (result == 1)
{
    /* 已请求恢复任务 */
}
```

**注意事项**

- 该函数没有检查目标任务是否此前确实处于挂起状态。
- 标准任务的判断条件是 `OS_PROCESS_OK[id] == 0`，不只是检查一个独立的挂起状态字段。
- 函数返回成功表示相关标志已更新并请求调度，不保证任务立即运行。
- 恢复操作不等同于重新创建任务。

### os_task_exit

**函数原型**

```c
void os_task_exit(void);
```

**参数说明**

无。

**返回值**

无。

**功能说明**

该函数用于请求当前任务退出。

函数读取 `OS_CURRENT_TASK`，然后根据任务类型修改对应的调度标志。

对于标准任务，函数清除 `OS_PROCESS_OK[id]` 的最低位，将 `OS_TASK[id].state` 设置为 `DEAD`，并清除 `wait_tick`。

对于高速任务，函数清除对应的高速任务运行标志、等待相关标志，并设置相应的删除标志。

随后，函数设置 `OS_SCHED_REASON`，恢复中断使能，并通过设置 `TF0 = 1` 请求 Timer0 中断处理后续调度。

**使用示例**

```c
void worker_task(void)
{
    /* 执行任务工作 */

    if (/* 退出条件成立 */)
    {
        os_task_exit();
    }

    /* 退出路径之后不应依赖当前任务继续执行 */
}
```

**注意事项**

- 函数没有返回值，也没有通过普通返回值报告退出操作是否成功。
- 当前实现标记任务状态并触发调度，实际资源清理由系统后续流程处理。
- 不应将其描述为函数内部立即完成所有堆栈及上下文资源释放。
- 当前实现没有检查当前任务是否为任务 `0`。调用方应避免对系统空闲任务执行不符合设计预期的退出操作。
- 该函数会直接将 `EA` 置为 `0` 后再置为 `1`，不保留调用前的中断使能状态。

### os_task_delete

**函数原型**

```c
char os_task_delete(unsigned char id);
```

**参数说明**

| 参数 | 类型 | 说明 |
|---|---|---|
| `id` | `unsigned char` | 要删除的任务编号 |

**返回值**

- `1`：删除标志设置成功。
- `-1`：任务编号无效，或尝试删除任务 `0`。

**功能说明**

该函数用于请求删除指定任务。

函数首先拒绝任务编号 `0`，并检查编号是否超过标准任务和高速任务所允许的范围。

对于高速任务，函数清除对应的运行标志和等待相关标志，并设置相应的高速任务删除标志。

对于标准任务，函数清除 `OS_PROCESS_OK[id]` 的最低位，将任务状态设置为 `DEAD`，并清除 `wait_tick`。

操作完成后，函数恢复中断使能并返回 `1`。

**使用示例**

```c
char result;

result = os_task_delete(1);

if (result == 1)
{
    /* 删除请求已提交 */
}
```

**注意事项**

- 该函数并未在自身实现中完成全部资源释放，而是设置删除相关标志，供后续清理流程处理。
- 返回 `1` 不等于任务上下文、堆栈及相关资源已经全部释放。
- 任务 `0` 不允许通过该接口删除。
- 当前实现没有明确拒绝删除正在运行的其他任务，也没有单独检查目标任务是否已注册。
- 函数通过 `EA = 0` 和 `EA = 1` 处理临界区，但没有恢复调用前的中断使能状态。

### os_task_set_priority

**函数原型**

```c
char os_task_set_priority(unsigned char id, unsigned char pr);
```

**参数说明**

| 参数 | 类型 | 说明 |
|---|---|---|
| `id` | `unsigned char` | 目标任务编号 |
| `pr` | `unsigned char` | 目标优先级，标准任务为 `0` 至 `7`，高速任务为 `8` |

**返回值**

- `0`：标准任务优先级修改成功，或高速任务保持高速类型且无需转换。
- 正数：任务类型转换成功，并返回转换后分配的任务编号。
- `-1`：参数无效、任务状态不允许修改，或目标任务类型转换时未能分配所需槽位。

**功能说明**

该函数在临界区中检查任务编号、优先级范围、任务删除状态和任务类型相关条件。

对于标准任务：

- 当目标优先级处于标准范围时，函数修改 `OS_PROCESS_OK[id]` 中的优先级位，设置调度请求并触发 Timer0 中断，返回 `0`。
- 当目标优先级为高速任务优先级时，函数尝试分配一个可用的高速任务槽位，并迁移任务上下文、堆栈指针及相关状态。成功后返回新的高速任务编号。

对于高速任务：

- 当目标优先级处于标准范围时，函数尝试申请一个可用的标准任务编号，将高速任务上下文和堆栈信息迁移到标准任务结构中。成功后返回新的标准任务编号。
- 当目标优先级仍为高速任务优先级时，函数返回 `0`，不执行任务类型转换。

任务类型转换需要可用的目标任务槽位，因此可能因资源不足而失败。

**使用示例**

```c
char result;

result = os_task_set_priority(1, 5);

if (result == 0)
{
    /* 标准任务优先级修改成功 */
}
else if (result > 0)
{
    /* 任务类型转换成功，result 为新任务编号 */
}
else
{
    /* 修改失败 */
}
```

**注意事项**

- 优先级参数的有效范围由 `OS_SCHED_LEVEL_MAX` 决定；按当前实现，允许的最高输入值为 `OS_SCHED_LEVEL_MAX - 2`。
- 标准任务优先级直接修改与标准任务、高速任务之间的类型转换是不同操作。
- 类型转换涉及任务编号和上下文迁移，调用方必须根据返回值更新对任务编号的引用。
- 任务 `0` 不允许修改优先级。
- 当前实现对高速任务还有额外的上下文标记和等待标志检查，因此并非任何高速任务都能在任意状态下修改优先级。
- 该函数直接使用 `EA = 0` 和 `EA = 1` 管理临界区，不会恢复调用前的中断使能状态。

### os_task_get_priority

**函数原型**

```c
char os_task_get_priority(unsigned char id);
```

**参数说明**

| 参数 | 类型 | 说明 |
|---|---|---|
| `id` | `unsigned char` | 要查询的任务编号 |

**返回值**

- 标准优先级：通常为 `0` 至 `7`。
- 高速优先级：当前实现返回 `OS_SCHED_LEVEL_MAX - 2`。
- `-1`：任务编号超出允许范围。

**功能说明**

该函数通过任务编号判断任务类型。

对于满足 `id < OS_PROCESS_MAX - 1` 的任务，函数从 `OS_PROCESS_OK[id]` 中提取优先级位并返回。

对于其他合法编号，函数直接返回 `OS_SCHED_LEVEL_MAX - 2`，即高速任务优先级编码。

**使用示例**

```c
char prio;

prio = os_task_get_priority(1);
```

**注意事项**

- 当前实现的标准任务判断条件是 `id < OS_PROCESS_MAX - 1`，而不是 `id < OS_PROCESS_MAX`。
- 因此，编号为 `OS_PROCESS_MAX - 1` 的最后一个标准任务不会按标准任务路径提取优先级，而会进入高速任务优先级返回路径。
- 这是当前实现中需要重点核对的边界条件。正式文档不应掩盖这一实现差异，修正源码后应同步更新接口说明。
- 当前函数不会检查任务是否已注册或处于有效状态。

### os_task_is_valid

**函数原型**

```c
signed char os_task_is_valid(u8 id);
```

**参数说明**

| 参数 | 类型 | 说明 |
|---|---|---|
| `id` | `u8` | 要检查的任务编号 |

**返回值**

- `1`：任务被识别为已注册。
- `0`：任务未注册。
- `-1`：任务编号超出允许范围。

**功能说明**

该函数检查指定编号对应的任务注册标记。

对于标准任务，函数通过 `OS_PROCESS_OK[id]` 是否非零判断注册状态。

对于两个高速任务，函数分别检查 `OS_SP_KUAI_BEI[]` 中对应的上下文标记。

**使用示例**

```c
signed char valid;

valid = os_task_is_valid(1);

if (valid == 1)
{
    /* 任务被识别为已注册 */
}
```

**注意事项**

- 对标准任务而言，只要 `OS_PROCESS_OK[id]` 非零，函数就返回 `1`；它并不要求任务当前处于就绪状态。
- 该接口检查的是实现定义的注册标记，不等同于全面验证任务当前能否运行。
- 需要判断任务是否就绪时，应使用 `os_task_get_state()` 等相关接口辅助判断。

### os_task_self

**函数原型**

```c
u8 os_task_self(void);
```

**参数说明**

无。

**返回值**

当前内核记录的任务编号，即 `OS_CURRENT_TASK`。

**功能说明**

函数直接返回 `OS_CURRENT_TASK`，用于获取系统当前记录的运行任务编号。

**使用示例**

```c
u8 my_id;

my_id = os_task_self();
```

**注意事项**

- 函数只返回当前任务编号，不检查该编号对应的任务是否仍然有效。
- 在任务编号发生变化或执行任务类型转换的场景中，应结合具体操作的返回值处理任务编号。

### os_task_yield

**函数原型**

```c
void os_task_yield(void);
```

**参数说明**

无。

**返回值**

无。

**功能说明**

函数设置 `OS_SCHED_REASON = 1`，然后通过 `TF0 = 1` 请求 Timer0 中断，以触发系统调度。

**使用示例**

```c
void worker_task(void)
{
    while (1)
    {
        /* 执行一段工作 */

        os_task_yield();
    }
}
```

**注意事项**

- 当前实现只设置调度请求并触发 Timer0 中断，没有直接修改标准任务的就绪位。
- 该函数不保证调用后一定切换到另一个任务；最终运行结果取决于调度器的处理逻辑。
- 不能仅凭函数名称认定其一定会重置时间片或强制切换任务。

### os_task_suspend_self

**函数原型**

```c
void os_task_suspend_self(void);
```

**参数说明**

无。

**返回值**

无。

**功能说明**

函数读取 `OS_CURRENT_TASK`，根据当前任务类型清除相应的就绪或运行标志，然后设置调度请求并触发 Timer0 中断。

对于标准任务，函数清除 `OS_PROCESS_OK[id]` 的最低位。

对于高速任务，函数清除对应的高速任务运行标志。

**使用示例**

```c
void worker_task(void)
{
    /* 执行任务工作 */

    os_task_suspend_self();

    /* 后续代码是否执行取决于任务何时恢复并再次运行 */
}
```

**注意事项**

- 该函数不会直接清除任务注册标记，也不会执行任务删除。
- 恢复任务需要其他执行路径调用 `os_task_resume()`，并且目标任务必须仍满足恢复条件。
- 当前实现没有在函数内使用 `EA = 0` 保护相关标志修改。
- 函数不保证立即切换完成，实际切换由后续调度处理执行。


无。

**返回值**

无。

**功能说明**

函数将 `OS_CFG_LOCK` 设置为 `1`，表示系统任务注册配置进入锁定状态。

- 当前函数本身只设置配置锁标志。
- 具体哪些任务注册接口会检查该标志，需要结合相应的任务注册实现确认。

### os_unlock

**函数原型**

```c
void os_unlock(void);
```

**参数说明**

无。

**返回值**

无。

**功能说明**

函数将 `OS_CFG_LOCK` 设置为 `0`，解除任务注册配置锁定状态。

**使用示例**

```c
os_unlock();
```

**注意事项**

- 该接口只修改注册配置锁标志。
- 它不负责恢复任务状态，也不负责解锁互斥锁或其他同步资源。
- 如果系统要求运行期间禁止继续注册任务，应结合注册接口对 `OS_CFG_LOCK` 的检查逻辑使用。

### os_lock_query

**函数原型**

```c
char os_lock_query(void);
```

**参数说明**

无。

**返回值**

- `1`：注册配置处于锁定状态。
- `0`：注册配置未锁定。

**功能说明**

函数读取 `OS_CFG_LOCK`，根据其当前值返回锁状态。

**使用示例**

```c
char locked;

locked = os_lock_query();

if (locked == 1)
{
    /* 注册配置已锁定 */
}
```

**注意事项**

- 查询结果反映的是系统注册配置锁状态。
- 它不代表 CPU 中断已关闭，也不代表任务调度已停止。
- 该接口不会改变锁状态。

## 使用建议

- **区分状态、注册与就绪。** 任务已注册并不意味着它当前可运行；应根据操作目的选择状态查询或注册检查接口。
- **谨慎使用指定下一次调度目标的接口。** `os_task_set_next()` 会直接更新内核记录的当前任务和前一任务编号，使用前应确认目标任务状态及调度上下文。
- **正确处理删除流程。** `os_task_delete()` 和 `os_task_exit()` 会设置删除相关标志，实际资源清理由后续内核流程完成。
- **修改优先级后更新任务编号引用。** 标准任务与高速任务之间转换时，返回值可能是新的任务编号。
- **不要将注册配置锁当作通用互斥锁。** `os_lock()` 和 `os_unlock()` 操作的是 `OS_CFG_LOCK`。
- **注意任务编号边界。** 尤其是最后一个标准任务与两个高速任务的编号边界，需与当前源码及配置保持一致。
- **避免依赖未经确认的状态语义。** `os_task_get_state()` 的返回值是通过多项内核变量计算得到的，使用时应以实际实现为准。
