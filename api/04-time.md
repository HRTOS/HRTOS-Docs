# 时间管理模块

## 模块简介

HRTOS 时间管理模块提供系统 Tick 计数、任务延时、时间单位转换、系统运行时间查询以及 Timer0 定时参数配置等功能。

模块通过 Timer0 维护系统时间计数，并通过 `os_wait()` 将任务延时接入内核等待机制。对于短时间、必须持续占用处理器的硬件时序等待，模块还提供忙等待函数 `os_delay_ms()`。

时间管理模块主要包含两种延时方式：

- **忙等待延时**：持续占用 CPU，不主动让出处理器，适用于短时间硬件时序控制。
- **任务延时**：通过内核等待机制等待指定数量的 Tick，适用于任务中的常规延时。

## 设计目标

- 提供系统 Tick 累计计数。
- 支持基于 Tick 的任务延时。
- 提供毫秒、秒与 Tick 数之间的换算接口。
- 支持系统累计运行时间查询。
- 支持配置系统 Tick 周期相关参数。
- 为硬件时序控制和任务级时间管理提供不同的接口。

## 适用场景

- 任务周期性执行与延时等待。
- 系统运行时间统计。
- 基于 Tick 的时间参数换算。
- 外设初始化、短脉冲控制等硬件时序等待。
- 系统定时参数配置与时间行为测试。

## 时间单位与配置

本模块使用系统配置和内部状态维护时间参数。常见配置项包括：

| 配置项 | 说明 |
|---|---|
| `OS_TIME_ONCE_DEFAULT` | 系统时间片相关的默认配置值，具体作用以系统配置及调度实现为准 |
| `OS_TIME_T0` | Timer0 定时参数相关配置项，具体含义以系统配置和初始化代码为准 |
| `OS_TIME_ONCE` | 当前配置的时间片计数参数，由 `os_tick_config()` 设置 |
| `OS_T0_TH0`、`OS_T0_TL0` | 用于计算 Tick 时间的 Timer0 重载值相关变量 |
| `OS_TICK_COUNT_H`、`OS_TICK_COUNT_L` | 系统累计 Tick 计数的高、低 16 位 |

需要注意，源码中的 `tick_value` 参数会经过重载值转换。调用者传入的值不是直接写入 Timer0 的最终重载值，而是先计算：

`65536 - tick_value`

因此，理解配置参数时应区分传入的计数值与最终写入的 Timer0 重载值。

| 函数 | 功能 |

## API 详细说明

### os_delay_ms

**函数原型**

```c
void os_delay_ms(unsigned char ms);
```

**功能说明**

执行毫秒级忙等待。函数通过循环消耗处理器执行时间，不调用内核等待接口，也不主动请求任务调度。

**参数**

| 参数 | 说明 |
|---|---|
| `ms` | 忙等待循环次数对应的延时参数，类型为 `unsigned char` |

**返回值**

无。

**调用示例**

```c
os_delay_ms(10);
```

**使用注意**

- 函数执行期间持续占用 CPU。
- 不会主动释放处理器供其他任务运行。
- 实际延时受 CPU 时钟、指令执行时间、编译器优化及中断干扰等因素影响。
- 参数表示函数内部循环次数所对应的延时量，不应将其视为跨时钟频率、跨编译配置都严格准确的毫秒计时。
- 适用于短时间硬件时序等待，不适合替代任务延时接口。

### os_ms_to_tick

**函数原型**

```c
u16 os_ms_to_tick(u16 ms);
```

**功能说明**

将输入的毫秒数换算为系统 Tick 数。

函数根据 `OS_T0_TH0` 和 `OS_T0_TL0` 计算当前 Tick 对应的计数值，再将其除以 1000，得到以整数毫秒表示的 Tick 时间。若计算结果小于 1 毫秒，则按 1 毫秒进行换算。

返回值使用向上取整的整数除法：

```c
(ms + tick_ms - 1) / tick_ms
```

**参数**

| 参数 | 说明 |
|---|---|
| `ms` | 待换算的毫秒数 |

**返回值**

返回换算得到的 Tick 数。

**调用示例**

```c
u16 ticks = os_ms_to_tick(100);
```

**使用注意**

- 换算结果依赖当前 Timer0 重载值。
- 函数使用整数运算，Tick 时间先换算为整数毫秒，存在精度损失。
- 该函数不是基于完整硬件时钟模型的高精度时间换算工具。
- 当输入值与中间计算结果接近 `u16` 的取值上限时，应注意整数运算溢出的可能性。

### os_sec_to_tick

**函数原型**

```c
u16 os_sec_to_tick(u8 sec);
```

**功能说明**

将输入的秒数转换为系统 Tick 数。

函数首先根据 Timer0 重载值计算单个 Tick 对应的整数毫秒数，再通过 `1000 / tick_ms` 计算每秒对应的 Tick 数，最后乘以输入秒数。

**参数**

| 参数 | 说明 |
|---|---|
| `sec` | 待换算的秒数，类型为 `u8` |

**返回值**

返回换算得到的 Tick 数。

**调用示例**

```c
u16 ticks = os_sec_to_tick(5);
```

**使用注意**

- 换算结果依赖当前 Timer0 配置。
- 计算过程使用整数除法，可能产生精度损失。
- 当 Tick 周期不能整除 1000 毫秒时，计算得到的每秒 Tick 数可能与实际时间存在偏差。
- `sec` 的取值范围受 `u8` 类型限制，返回结果还应考虑 `u16` 的表示范围。

### os_tick_config

**函数原型**

```c
char os_tick_config(u8 slice_count, u16 tick_value);
```

**功能说明**

配置系统时间片相关参数及 Timer0 重载值，并将系统累计 Tick 计数清零。

函数执行过程如下：

- 检查 `slice_count` 是否为 0；若为 0，返回 `-1`。
- 将 `slice_count` 写入 `OS_TIME_ONCE`。
- 检查 `tick_value` 是否大于 1000；若不满足，返回 `-1`。
- 清零 `OS_TICK_COUNT_H` 和 `OS_TICK_COUNT_L`。
- 根据 `65536 - tick_value` 计算重载值，并写入 `OS_T0_TH0`、`OS_T0_TL0`。
- 配置成功时返回 `0`。

**参数**

| 参数 | 说明 |
|---|---|
| `slice_count` | 写入 `OS_TIME_ONCE` 的时间片相关计数参数，不能为 0 |
| `tick_value` | 用于计算 Timer0 重载值的计数参数，必须大于 1000 |

**返回值**

| 返回值 | 含义 |
|---|---|
| `0` | 配置成功 |
| `-1` | 参数检查失败 |

**调用示例**

```c
char result = os_tick_config(5, 10000);

if (result == 0)
{
    /* 配置成功 */
}
```

**使用注意**

- `tick_value` 必须大于 1000，且受 `u16` 类型范围限制。
- 该函数写入 `OS_TIME_ONCE` 的操作发生在 `tick_value` 合法性检查之前。因此，如果 `slice_count` 合法而 `tick_value` 不合法，函数虽然返回 `-1`，`OS_TIME_ONCE` 仍然会被修改。
- 配置成功时会清零累计 Tick 计数，调用后系统累计时间计数不再保留原值。
- 函数没有在内部停止 Timer0，也没有对整个配置过程进行显式的中断保护。应结合系统初始化顺序和实际运行状态选择调用时机。
- 参数的实际计时意义取决于 Timer0 工作模式、计数时钟及相关初始化配置。不能仅凭此函数保证实际时间精度。

### os_tick_get

**函数原型**

```c
void os_tick_get(u16 *high, u16 *low);
```

**功能说明**

读取系统累计 Tick 计数，并分别通过两个指针返回高 16 位和低 16 位。

组合方式如下：

```c
u32 total_ticks = ((u32)high_value << 16) | low_value;
```

**参数**

| 参数 | 说明 |
|---|---|
| `high` | 接收系统 Tick 计数高 16 位的指针 |
| `low` | 接收系统 Tick 计数低 16 位的指针 |

**返回值**

无。

**调用示例**

```c
u16 high;
u16 low;

os_tick_get(&high, &low);

u32 total_ticks = ((u32)high << 16) | low;
```

**使用注意**

- 两个计数值分别保存在 `OS_TICK_COUNT_H` 和 `OS_TICK_COUNT_L` 中。
- 函数在读取时关闭 Timer0 中断使能 `ET0`，读取完成后将 `ET0` 设置为 1。
- 当前实现没有保存并恢复调用前的 `ET0` 状态。如果调用前 Timer0 中断已关闭，函数返回后仍会将其打开。
- 函数没有检查输出指针是否为空，调用者应传入有效的指针。
- 该函数只读取累计 Tick 计数，不直接返回毫秒或微秒。

### os_uptime_ms

**函数原型**

```c
u32 os_uptime_ms(void);
```

**功能说明**

根据系统累计 Tick 计数和当前 Timer0 重载值，估算系统累计运行时间，并以毫秒为单位返回。

函数首先读取高、低 16 位 Tick 计数，组合为 32 位累计计数；随后根据 Timer0 重载值计算单个 Tick 对应的整数毫秒数，最后将累计 Tick 数乘以该整数毫秒数。

核心计算关系为：

```c
total_tick = ((u32)tick_h << 16) | tick_l;

tick_us = 65536 - tick_value;
tick_ms = tick_us / 1000;

if (tick_ms == 0)
{
    tick_ms = 1;
}

uptime_ms = total_tick * tick_ms;
```

以上为计算逻辑的示意表达，实际执行过程以函数源码为准。

**参数**

无。

**返回值**

返回 `u32` 类型的系统累计运行时间估算值，单位为毫秒。

**调用示例**

```c
u32 uptime = os_uptime_ms();
```

**使用注意**

- 返回值基于累计 Tick 数估算，不是直接读取独立的毫秒硬件计时器。
- 计算时使用整数除法；当单个 Tick 不能整除 1000 微秒时，会产生精度损失。
- 当计算出的 Tick 毫秒数为 0 时，函数按 1 毫秒处理。
- 读取 Tick 计数时，函数关闭 `ET0`，随后将 `ET0` 设置为 1，没有恢复调用前的中断使能状态。
- Tick 计数读取与 Timer0 重载值读取不是一个完整的受保护操作。如果运行期间重新配置定时参数，计数与换算参数可能不一致。
- `u32` 返回值具有有限范围，长时间运行时需要考虑计数回绕风险。
- 当前实现没有使用浮点运算。

### os_delay

**函数原型**

```c
void os_delay(u16 tick);
```

**功能说明**

让当前任务通过内核等待机制延时指定数量的 Tick。

当 `tick` 为 0 时，函数直接返回。当 `tick` 不为 0 时，函数先检查当前任务 ID 是否小于 `OS_PROCESS_MAX + 2`。满足条件时，设置 Timer0 计数寄存器 `TL0` 和 `TH0`，随后调用：

```c
os_wait(WAIT_DELAY, OS_INVALID_ID, tick);
```

由内核等待机制处理当前任务的延时等待。

**参数**

| 参数 | 说明 |
|---|---|
| `tick` | 请求延时的系统 Tick 数 |

**返回值**

无。

**调用示例**

```c
os_delay(100);
```

**使用注意**

- `tick == 0` 时不会进入等待流程。
- 对于当前任务 ID 小于 `OS_PROCESS_MAX + 2` 的情况，函数会调用内核等待接口。
- 如果当前任务 ID 不满足检查条件，函数不会调用 `os_wait()`。
- 函数会直接修改 `TL0` 和 `TH0`，因此延时调用与 Timer0 计时行为之间的具体关系需要结合系统定时器中断代码确认。
- 实际等待时间取决于系统 Tick 配置、内核等待机制以及调度行为。
- 该函数的意图是执行任务级延时，而不是忙等待。其是否释放处理器、何时重新进入就绪状态，以及高速任务的具体处理方式，应以 `os_wait()` 和对应的唤醒实现为准。

## 使用建议

### 选择合适的延时接口

| 使用需求 | 建议接口 | 说明 |
|---|---|---|
| 短时间硬件时序等待 | `os_delay_ms()` | 忙等待，占用 CPU |
| 按 Tick 延时当前任务 | `os_delay()` | 通过内核等待机制处理 |
| 毫秒参数转换 | `os_ms_to_tick()` | 返回估算的 Tick 数 |
| 秒参数转换 | `os_sec_to_tick()` | 返回估算的 Tick 数 |
| 读取累计 Tick | `os_tick_get()` | 获取高、低 16 位 |
| 查询累计运行时间 | `os_uptime_ms()` | 返回基于 Tick 的毫秒估算值 |
| 配置系统定时参数 | `os_tick_config()` | 修改时间片相关参数及 Timer0 重载值 |

### 配置与精度注意事项

时间管理模块的多个接口使用 Timer0 重载值进行整数换算。由于代码采用整数除法，转换结果和累计运行时间均可能存在量化误差。

如果需要更高的时间精度，应结合实际晶振频率、Timer0 工作模式、定时器中断实现和调度开销进行验证，不应将本模块返回的毫秒数直接视为严格精确的墙钟时间。

在系统运行期间修改 Tick 配置时，还应确认累计计数是否需要保留、Timer0 是否正在运行，以及其他时间相关模块是否依赖原有配置。

## 使用说明

- **系统 Tick**：时间接口的换算精度与实际行为取决于系统 Tick 配置及定时器运行情况。
- **忙等待延时**：`os_delay_ms()` 通过软件循环实现延时，会持续占用 CPU，实际延时受处理器运行频率、编译器优化及中断执行等因素影响。
- **时间单位转换**：`os_ms_to_tick()` 和 `os_sec_to_tick()` 根据系统 Tick 配置进行整数换算，转换结果可能存在取整误差。
- **Tick 配置**：调用 `os_tick_config()` 时，应确保传入的参数符合接口规定的有效范围。
- **中断状态**：使用 `os_tick_get()` 和 `os_uptime_ms()` 时，应注意接口对 Timer0 中断使能状态的处理，避免与应用程序自身的中断管理逻辑产生冲突。
- **任务延时**：`os_delay()` 通过内核等待机制实现基于 Tick 的任务延时，其实际行为取决于系统定时器、内核等待与任务唤醒机制的协同工作。
