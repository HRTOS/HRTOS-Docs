# 统一等待模块

## 模块简介

HRTOS 统一等待模块为任务延时和资源同步提供统一的等待状态管理机制。模块包含等待入口、资源对象初始化和任务唤醒接口，负责记录任务的等待类型、等待对象、等待计时参数及唤醒结果，并通过调度触发机制请求内核重新调度。

模块主要由以下接口构成：

- `os_wait()`：统一等待入口，处理延时等待和关联资源对象的等待。
- `os_res_init()`：初始化统一资源对象的基础状态。
- `wake_task()`：清理任务等待信息，并在允许唤醒时恢复其就绪资格。

标准任务和高速任务的延时处理路径有所不同。标准任务通过任务控制块记录等待状态；高速任务使用独立的运行标志和等待计数，不进入标准任务的统一等待处理路径。

## 设计目标

- 统一管理任务的等待状态与等待上下文。
- 为延时、信号量、互斥锁、消息及事件等机制提供公共等待基础。
- 使用资源等待位图记录关联资源的等待任务。
- 保存等待结果，使任务唤醒后能够获取相应状态。
- 通过调度请求与 Timer0 中断触发机制衔接内核调度。

## 适用场景

- 任务延时与超时等待。
- 信号量、互斥锁等同步对象的等待。
- 消息队列、邮箱及事件相关的等待。
- 任务等待状态的统一维护。
- 资源释放或其他事件发生后的任务唤醒。

具体资源机制如何选择等待者、如何判断资源条件满足，以及超时由何处检测，需要结合对应资源模块和系统定时处理代码理解。

## 核心数据结构

### OS_RESOURCE

`os_res_init()` 接收 `OS_RESOURCE` 类型的指针，并初始化该对象中的以下字段：

| 成员 | 初始化值 | 用途 |
|---|---|---|
| `value` | `0` | 资源相关数值 |
| `owner` | `OS_INVALID_ID` | 当前拥有者标识 |
| `wait_cnt` | `0` | 等待任务计数 |
| `wait_mask` | `0` | 等待任务位图 |

当前提供的 `os_res_init()` 实现没有初始化 `pending_signal` 字段。若该字段属于实际使用的资源结构体，初始化时是否需要清零，应结合对应中断信号处理逻辑确认。

资源结构体的完整定义应以 `hrtos.h` 或项目实际配置头文件为准，不应仅根据本模块的函数实现推断全部成员。

### 任务等待上下文

对于标准任务，`os_wait()` 通过 `OS_TASK[tid]` 保存等待信息：

| 字段 | 用途 |
|---|---|
| `wait_type` | 当前等待类型 |
| `wait_obj` | 关联的等待对象编号 |
| `wait_tick` | 等待计时参数 |
| `wait_flag` | 等待结果 |
| `state` | 任务状态 |

当任务进入等待时，函数将任务状态设为 `WAIT`，并清除 `OS_PROCESS_OK[tid]` 的最低位，使该任务不再具有正常调度资格。

任务被成功唤醒时，`wake_task()` 清理等待上下文、将状态设置为 `READY`，并重新置位相应的调度资格位。

## 等待类型与返回标志

本模块通过 `type` 参数区分等待类型。项目中的等待类型名称包括：

| 名称 | 含义 |
|---|---|
| `WAIT_NONE` | 当前没有等待 |
| `WAIT_DELAY` | 延时等待 |
| `WAIT_SEM` | 信号量等待 |
| `WAIT_MUTEX` | 互斥锁等待 |
| `WAIT_MSG_SEND` | 消息发送等待 |
| `WAIT_MSG_RECV` | 消息接收等待 |
| `WAIT_EVENT` | 事件等待 |
| `WAIT_MAILBOX` | 邮箱等待 |

上述名称及其具体数值应以项目实际配置为准。

`os_wait()` 的返回值和 `wake_task()` 的 `flag` 参数使用项目定义的等待结果标志。常见名称包括：

| 名称 | 含义 |
|---|---|
| `WAIT_TIMEOUT` | 超时结果 |
| `WAIT_SIGNAL` | 信号或正常唤醒结果 |

这些标志的具体数值应以项目头文件中的定义为准。

## API 函数列表

| 函数 | 功能 |
|---|---|
| `os_wait()` | 统一等待入口 |
| `os_res_init()` | 初始化资源对象 |
| `wake_task()` | 清理等待上下文并尝试唤醒任务 |

## API 详细说明

### os_wait

**函数原型**

```c
u8 os_wait(u8 type, u8 obj, u16 tick);
```

**功能说明**

使当前任务进入指定的等待流程。函数根据等待类型执行不同处理：延时等待使用专门路径；其他等待类型会检查当前任务是否已有等待状态，并验证资源对象编号，然后保存等待信息、更新资源等待位图，并请求调度。

**参数**

| 参数 | 类型 | 说明 |
|---|---|---|
| `type` | `u8` | 等待类型 |
| `obj` | `u8` | 等待对象编号；纯延时等待不依赖资源对象 |
| `tick` | `u16` | 等待计时参数，单位为系统 Tick |

**返回值**

返回 `u8` 类型的结果。具体返回行为如下：

| 情况 | 返回行为 |
|---|---|
| 延时等待且 `tick == 0` | 返回 `WAIT_TIMEOUT` |
| 高速任务执行非零延时等待 | 设置相应高速任务运行标志和等待计数后，返回 `WAIT_TIMEOUT` |
| 当前任务已有等待状态，且本次不是延时等待 | 返回 `0` |
| 非延时等待的对象编号超出 `OS_RESOURCE_MAX` 范围 | 返回 `0` |
| 标准任务完成等待状态登记 | 返回当前 `wait_flag` 字段的值 |

需要特别注意：标准任务登记等待后，函数在触发调度之前将 `wait_flag` 初始化为 `0`，随后返回该字段。因此，不能仅根据函数原型或注释，就认定所有调用都会在任务实际恢复执行后返回最终的 `WAIT_TIMEOUT` 或 `WAIT_SIGNAL`。

**标准任务等待流程**

对于标准任务，非零延时和资源等待均会记录任务等待上下文，并清除任务的正常调度资格位。资源等待还会在关联对象有效且不为 `OS_INVALID_ID` 时更新等待位图和等待计数。

主要处理过程如下：

- 保存等待类型、对象、计时参数，并将 `wait_flag` 清零。
- 对关联资源对象设置对应任务的等待位。
- 更新任务状态为 `WAIT`。
- 清除 `OS_PROCESS_OK[tid]` 的最低位。
- 设置 `OS_SCHED_REASON` 并置位 `TF0`，请求系统进入调度流程。

对于 `WAIT_DELAY`，代码不会将任务加入资源等待位图。

**高速任务延时流程**

当当前任务 ID 大于或等于 `OS_PROCESS_MAX` 时，函数进入高速任务专用分支。

- ID 等于 `OS_PROCESS_MAX` 时，清除高速任务 A 的运行标志，并将 `tick` 写入 `OS_WAIT_DI2[0]`。
- ID 等于 `OS_PROCESS_MAX + 1` 时，清除高速任务 B 的运行标志，并将 `tick` 写入 `OS_WAIT_DI2[1]`。
- 两种路径均设置调度请求并触发 Timer0 中断，然后返回 `WAIT_TIMEOUT`。

这一路径不会写入标准任务的 `wait_type`、`wait_obj`、`wait_tick` 和 `wait_flag`，也不会进入标准任务的资源等待位图处理流程。

**调用示例**

```c
/* 标准任务延时：具体行为取决于内核等待与唤醒实现 */
os_wait(WAIT_DELAY, OS_INVALID_ID, 10);

/* 等待资源编号 0：必须确保该资源已正确初始化 */
u8 result = os_wait(WAIT_SEM, 0, 10);
```

示例仅展示接口调用方式。资源等待是否成功、何时唤醒以及结果如何解释，应以相应资源模块和等待结果处理代码为准。

**使用注意**

- 当前实现通过 `EA = 0` 进入临界区，并在多个返回路径中设置 `EA = 1`，没有保存并恢复调用前的全局中断使能状态。
- 对非延时等待，函数会拒绝已经具有非 `WAIT_NONE` 等待类型的任务。
- 对非延时等待，函数会检查 `obj` 是否小于 `OS_RESOURCE_MAX`，但不会在本函数中验证等待类型是否属于已定义类型。
- `WAIT_DELAY` 使用独立路径，不执行相同的重复等待检查。
- 对标准任务，函数返回的是登记等待时读取的 `wait_flag`，而不是通过当前函数实现了一个显式的“挂起后再恢复执行”的同步等待循环。
- 超时扫描、资源条件检查和唤醒者选择并不由这段代码完整实现，需要继续检查对应内核代码。

### os_res_init

**函数原型**

```c
void os_res_init(OS_RESOURCE *r);
```

**功能说明**

初始化指定资源对象的基础状态，使其资源数值、拥有者和等待记录回到初始值。

**参数**

| 参数 | 类型 | 说明 |
|---|---|---|
| `r` | `OS_RESOURCE *` | 待初始化的资源对象指针 |

**返回值**

无。

**调用示例**

```c
OS_RESOURCE my_resource;

os_res_init(&my_resource);
```

**执行行为**

函数依次执行以下操作：

- 将 `value` 设为 `0`。
- 将 `owner` 设为 `OS_INVALID_ID`。
- 将 `wait_cnt` 设为 `0`。
- 将 `wait_mask` 设为 `0`。

**使用注意**

- 调用前必须确保 `r` 指向有效、可写的资源对象。
- 函数不会检查空指针。
- 当前实现没有初始化 `pending_signal` 等其他可能存在的成员。
- 资源初始化应在资源投入使用前完成，避免清除正在使用中的等待状态。

### wake_task

**函数原型**

```c
void wake_task(u8 tid, u8 flag);
```

**功能说明**

清理指定任务关联的等待记录，并在任务仍符合唤醒条件时设置唤醒结果、恢复就绪状态以及触发调度。

**参数**

| 参数 | 类型 | 说明 |
|---|---|---|
| `tid` | `u8` | 待处理的任务编号 |
| `flag` | `u8` | 写入任务等待结果的标志 |

**返回值**

无。

**执行流程**

函数首先关闭全局中断使能，并读取目标任务的 `wait_obj`。

如果 `wait_obj` 不等于 `OS_INVALID_ID`，函数会：

- 清除对应资源等待位图中属于该任务的位。
- 在 `wait_cnt` 非零时将其减一。

随后，函数检查目标任务是否已经删除或处于 `DEAD` 状态：

- 如果 `OS_PROCESS_OK[tid] == 0`，则恢复全局中断使能并返回。
- 如果 `OS_TASK[tid].state == DEAD`，则恢复全局中断使能并返回。

若任务通过上述检查，函数会：

- 将 `flag` 写入 `wait_flag`。
- 将 `wait_type` 设为 `WAIT_NONE`。
- 将 `wait_obj` 设为 `OS_INVALID_ID`。
- 将 `wait_tick` 设为 `0`。
- 将任务状态设为 `READY`。
- 设置 `OS_PROCESS_OK[tid]` 的最低位。
- 设置 `OS_SCHED_REASON`，恢复全局中断使能，并置位 `TF0` 请求调度。

**调用示例**

```c
/* 示例：由内核或相应同步机制在合适的上下文中调用 */
wake_task(task_id, WAIT_SIGNAL);
```

此示例中的 `task_id` 应是有效的任务编号，调用时机和 `flag` 的含义应与相应等待机制保持一致。

**使用注意**

- 函数没有在入口检查 `tid` 是否小于任务总数。调用者必须确保任务编号有效，否则访问任务控制块或资源数组可能越界。
- 函数会先尝试清理资源等待记录，然后才检查任务是否已删除或处于 `DEAD` 状态。因此，即使最终不执行唤醒，等待位图和等待计数也可能已经被修改。
- 函数没有验证目标任务当前是否确实处于等待状态。
- `flag` 会被直接写入 `wait_flag`，函数本身不会验证它是否为有效等待结果。
- 函数通过 `EA = 0` 和 `EA = 1` 控制中断使能，不会恢复调用前的中断状态。
- `wake_task()` 负责处理等待上下文和恢复就绪资格，但资源条件是否满足、应唤醒哪个任务等策略应由调用它的资源机制负责。

## 使用建议

### 延时与资源等待分开理解

`WAIT_DELAY` 表示纯时间等待，不需要关联资源等待位图。信号量、互斥锁、消息、邮箱和事件等等待则可能关联资源对象，具体由对应模块传入参数。

### 不要混淆等待登记与最终唤醒

调用 `os_wait()` 并不意味着所有路径都会同步返回最终的等待结果。标准任务路径先登记等待信息并请求调度；高速任务延时路径则采用独立的运行标志和等待计数。应结合调度器、定时器处理及具体资源模块理解完整执行过程。

### 保证任务编号和资源编号有效

`wake_task()` 不检查任务编号边界；`os_res_init()` 不检查指针有效性。使用这些接口时，应由调用者确保参数合法，并保证资源对象在整个等待期间有效。

### 注意中断状态管理

`os_wait()` 和 `wake_task()` 均会直接将全局中断使能设置为关闭或开启状态，没有完整保存和恢复进入函数前的中断状态。若这些函数可能在中断已关闭的上下文中调用，应特别审核相关路径。

## 使用说明

- **等待机制**：统一等待模块负责记录任务等待状态并配合唤醒处理，具体的资源获取、释放与同步规则由相应功能模块决定。
- **任务类型**：标准任务与高速任务采用不同的等待处理路径，具体行为应以对应任务类型的接口约定为准。
- **等待与返回值**：`os_wait()` 的返回值应结合任务调度、上下文恢复及调用模块的处理逻辑理解。调用相关接口时，应遵循对应模块规定的等待与唤醒语义。
- **任务唤醒**：调用 `wake_task()` 时，调用方必须确保任务编号有效，并正确处理任务当前状态及其等待关系。
- **资源初始化**：`os_res_init()` 初始化资源对象中由该函数明确设置的字段。其他字段的初始化要求应以资源结构定义及相关模块实现为准。
- **中断状态**：等待与唤醒相关操作应遵循系统的中断管理约定，避免破坏调用前的中断状态或影响内核调度。
