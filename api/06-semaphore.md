# 信号量模块

## 模块简介

HRTOS 信号量模块提供基于计数值的任务同步机制，通过 P/V 操作管理可用资源数量，并支持多个任务等待同一信号量。

信号量基于系统统一资源表 `OS_RES[]` 实现，使用资源槽位中的 `value` 保存计数，使用 `wait_mask` 记录等待任务。释放信号量时，如果存在等待任务，模块会尝试选择一个优先级较高的任务并唤醒；如果没有等待任务，则增加信号量计数。

信号量不使用资源拥有者机制，适用于任务同步、资源数量管理和事件协调等场景。它与互斥锁的主要区别是：信号量关注计数与同步，不以任务所有权作为获取和释放的基本条件。

## 设计目标

- 提供任务间的 P/V 同步操作。
- 使用计数值管理可用资源数量。
- 支持多个任务等待同一信号量。
- 在信号量可用时提供直接获取路径。
- 复用 HRTOS 统一资源表和任务等待机制。

## 使用场景

- **资源计数管理：** 限制同时使用某类资源的任务数量。
- **任务间同步：** 协调生产者与消费者等不同任务的执行。
- **事件协调：** 通过信号量通知其他任务继续执行。
- **有限资源访问：** 使用计数信号量表示可用资源数量。

需要注意，信号量本身不记录资源由哪个任务获取，也不提供与互斥锁相同的所有权约束。

## 数据结构

本模块复用 `hrtos_internal.h` 中定义的 `OS_RESOURCE` 资源结构，并通过 `OS_RES[sid]` 访问指定信号量。

| 字段 | 用途 |
|---|---|
| `value` | 信号量计数，表示当前记录的可用资源数量 |
| `owner` | 兼容统一资源结构，初始化时设为 `OS_INVALID_ID`；信号量逻辑不使用所有权机制 |
| `wait_mask` | 等待该资源的任务位图 |
| `wait_cnt` | 兼容字段，初始化时清零；当前所提供的信号量实现未使用该字段进行计数管理 |

信号量编号 `sid` 对应统一资源表中的槽位，因此必须满足：

```c
sid < OS_RESOURCE_MAX
```

## 宏定义

本模块没有单独定义公开宏。实现中使用的 `OS_RESOURCE_MAX`、`OS_INVALID_ID`、`WAIT_SEM`、`WAIT_SIGNAL`、`OS_PROCESS_MAX` 等标识符由 HRTOS 的其他配置或内核模块提供。

## API 函数列表

| 函数 | 功能 |
|---|---|
| `os_sem_init()` | 初始化指定信号量 |
| `os_sem_wait()` | 等待或获取一个信号量 |
| `os_sem_post()` | 释放信号量，或唤醒等待任务 |

## API 详细说明

### os_sem_init

**函数原型**

```c
char os_sem_init(u8 sid, u8 init_val);
```

**参数说明**

| 参数 | 类型 | 说明 |
|---|---|---|
| `sid` | `u8` | 信号量编号，对应资源表槽位 |
| `init_val` | `u8` | 信号量初始计数值 |

**返回值**

- `1`：初始化成功。
- `-1`：信号量编号超出有效范围。

**功能说明**

初始化指定的信号量，主要执行以下操作：

- 检查 `sid` 是否小于 `OS_RESOURCE_MAX`。
- 将 `value` 设置为传入的初始计数值。
- 将 `owner` 设置为 `OS_INVALID_ID`。
- 清空 `wait_mask`。
- 将 `wait_cnt` 设为 `0`。

**使用示例**

```c
char result;

result = os_sem_init(0, 2);

if (result == 1)
{
    /* 信号量 0 初始化成功 */
}
```

**注意事项**

- 初始化会直接覆盖指定资源槽位中的相关字段。
- 实现没有使用 `EA` 进行临界区保护，因此应在合适的初始化阶段调用，避免与正在运行的任务或等待操作并发访问同一资源。
- 不应在仍有任务等待该信号量时随意重新初始化，否则可能破坏现有等待关系。
- 当前实现将 `wait_cnt` 清零，但信号量的等待任务选择主要依赖 `wait_mask`。

### os_sem_wait

**函数原型**

```c
u8 os_sem_wait(u8 sid);
```

**参数说明**

| 参数 | 类型 | 说明 |
|---|---|---|
| `sid` | `u8` | 信号量编号 |

**返回值**

- `0`：信号量编号无效。
- `WAIT_SIGNAL`：计数获取路径返回的成功标识。
- 其他值：可能来自 `os_wait()` 的返回结果，具体含义取决于内核等待机制的实现。

**功能说明**

该函数用于执行信号量 P 操作。源码首先检查信号量编号，然后进入计数检查流程。

当计数大于零时，函数将计数减一，并返回 `WAIT_SIGNAL`。

当计数为零时，函数会保存当前任务的基础优先级，重新开启中断，再调用：

```c
tid = os_wait(WAIT_SEM, sid, 0);
```

等待内核处理任务阻塞和后续唤醒。`WAIT_SEM` 用于标识信号量等待类型，最后一个参数传入 `0`。

从当前实现看，`os_wait()` 返回后，函数还会再次检查信号量计数：如果计数大于零，则减一并返回 `WAIT_SIGNAL`；否则返回 `tid`，即保存的 `os_wait()` 返回值。

**使用示例**

```c
u8 result;

result = os_sem_wait(0);

if (result == WAIT_SIGNAL)
{
    /* 按照返回值判断获取结果 */
}
```

**注意事项**

- 当信号量计数为零时，该函数可能进入任务等待流程。
- 当前 API 没有提供独立的超时参数，不能仅根据本函数的接口承诺超时等待能力。
- 不要直接把所有非 `WAIT_SIGNAL` 的返回值都解释为超时；其含义需要结合 `os_wait()` 的实现确认。
- 当前代码在调用 `os_wait()` 前已经执行 `EA = 1`。计数检查与等待登记之间是否存在竞争窗口，需要结合内核等待实现进一步验证。
- 如果唤醒后计数仍为零，函数会返回 `os_wait()` 的结果，而不是无条件返回 `WAIT_SIGNAL`。因此，调用方应在确认内核返回语义后，再确定可靠的成功判定方式。

### os_sem_post

**函数原型**

```c
char os_sem_post(u8 sid);
```

**参数说明**

| 参数 | 类型 | 说明 |
|---|---|---|
| `sid` | `u8` | 信号量编号 |

**返回值**

- `1`：资源的等待位图非零，函数执行了等待任务处理分支。
- `0`：没有等待任务，函数完成计数处理。
- `-1`：信号量编号无效。

需要注意，源码在等待位图非零时会尝试选择任务并调用 `wake_task()`。即使最终没有选出有效任务，该分支仍然返回 `1`，所以该返回值不应直接理解为“已确认成功唤醒一个任务”。

**功能说明**

该函数用于执行信号量 V 操作。源码首先检查编号，然后通过 `EA = 0` 进入临界区。

如果 `wait_mask` 非零，函数遍历任务位图，选择 `OS_TASK[i].base_prio` 最大的等待任务，并调用：

```c
wake_task(next, WAIT_SIGNAL);
```

此分支不增加信号量计数，而是尝试直接唤醒等待任务。

如果没有等待任务，函数检查当前计数是否小于 `255`。只有在小于 `255` 时才执行 `value++`，从而避免计数超过一个字节能够表示的最大值。随后函数恢复中断并返回 `0`。

**使用示例**

```c
char result;

result = os_sem_post(0);

if (result == 1)
{
    /* 存在等待任务，已执行唤醒处理分支 */
}
else if (result == 0)
{
    /* 没有等待任务，已完成计数处理 */
}
else
{
    /* 信号量编号无效 */
}
```

**注意事项**

- 有等待任务时，当前实现优先执行唤醒分支，而不是增加计数。
- 没有等待任务时，计数最多累加到 `255`；达到上限后再次调用不会继续增加计数。
- 任务选择依据是 `base_prio`，不是 `cur_prio`。
- 当前源码没有提供独立的 `os_sem_post_from_isr()` 接口，不能据此宣称本模块具备专用的中断释放 API。
- 函数通过 `EA = 0` 和 `EA = 1` 保护临界区，但没有保存并恢复调用前的中断使能状态。

## 使用建议

- **合理设置初始计数。** 初始计数值应与需要管理的资源数量或同步场景相匹配。
- **区分信号量与互斥锁。** 信号量不跟踪持有者，不应将其视为具备完整所有权检查的互斥锁。
- **谨慎处理等待返回值。** 应结合 `os_wait()` 和 `wake_task()` 的具体实现确认阻塞、唤醒及返回值的对应关系。
- **避免重复初始化活动中的信号量。** 重新初始化会清空等待位图，可能影响已有等待任务。
- **注意计数上限。** `value` 的实际计数累加上限为 `255`。
- **评估临界区使用方式。** 当前实现直接将 `EA` 置为 `0`，结束时再置为 `1`，调用前若中断已经关闭，函数返回时也会将其打开。
- **不要默认支持中断上下文调用。** 应在确认内核调度、等待和唤醒机制的约束后，再确定各接口的可调用上下文。


## 使用说明

- **计数机制**：信号量通过计数值管理资源的可用状态，并配合统一等待机制处理任务等待与唤醒。
- **资源获取**：使用信号量时，应根据接口定义处理获取结果，并遵循对应的等待与唤醒约定。
- **资源释放**：释放信号量时，应确保调用符合模块规定的使用方式，避免因不恰当的调用影响任务调度。
- **并发使用**：在多个任务或中断共同访问信号量的场景中，应结合系统的调度机制和中断管理规则设计同步流程。
- **中断上下文**：不要默认所有信号量接口均可在中断服务程序中安全调用；应以接口明确规定的调用上下文为准。
