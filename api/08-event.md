# 事件模块

## 模块简介

HRTOS 事件模块提供基于事件状态的任务同步机制。任务可以等待指定事件，其他任务或中断处理代码可以通过事件触发接口设置事件状态，并唤醒等待该事件的任务。

事件模块基于统一资源对象 `OS_RESOURCE` 实现，使用资源对象的 `value` 字段记录事件状态，并通过 `wait_mask` 和 `wait_cnt` 管理等待任务。

模块提供事件初始化、事件触发、事件等待、状态查询和事件删除接口。

### 设计特点

- **事件状态保持：** 事件触发后，`value` 被设置为 `1`，后续查询或等待操作可以检查该状态。
- **多任务唤醒：** 触发事件时，遍历等待位图，对其中标记的任务调用唤醒接口。
- **支持超时等待：** 事件尚未触发时，通过统一等待接口进入事件等待流程。
- **统一资源管理：** 事件使用 HRTOS 的统一资源对象，不单独定义事件控制块结构。
- **接口分离：** 提供独立的初始化、触发、等待、查询和删除函数。

### 适用场景

- 多个任务等待同一个条件成立
- 任务之间进行状态变化通知
- 任务等待外部事件或中断产生的通知
- 需要查询某个事件当前是否已经触发的场景

## 数据结构

事件模块使用系统配置模块定义的 `OS_RESOURCE` 结构。

```c
typedef struct
{
    u8 value;
    u8 owner;
    u8 wait_cnt;
    u16 wait_mask;
    u8 pending_signal;
} OS_RESOURCE;
```

事件模块主要使用以下成员：

| 成员 | 作用 |
|---|---|
| `value` | 记录事件状态，事件未触发时为 `0`，触发后设置为 `1` |
| `wait_cnt` | 记录等待任务数量 |
| `wait_mask` | 使用位图标记等待任务 |

事件对象编号对应统一资源对象数组 `OS_RES` 的下标，有效范围为 `0` 至 `OS_RESOURCE_MAX - 1`。当前配置中，`OS_RESOURCE_MAX` 为 `6`。

事件模块不单独定义公开的事件 ID 类型或事件专用控制块。

## API 函数列表

| 函数 | 功能 |
|---|---|
| `os_event_init()` | 初始化指定事件资源 |
| `os_event_write()` | 触发事件并尝试唤醒等待任务 |
| `os_event_wait()` | 等待事件触发 |
| `os_event_query()` | 查询事件触发状态 |
| `os_event_delete()` | 清除事件触发状态 |

## 事件初始化 os_event_init

### 函数原型

```c
char os_event_init(u8 obj);
```

### 参数说明

| 参数 | 类型 | 说明 |
|---|---|---|
| `obj` | `u8` | 事件资源槽位编号 |

### 返回值

| 返回值 | 说明 |
|---|---|
| `1` | 初始化成功 |
| `-1` | 事件资源槽位编号无效 |

### 功能说明

初始化指定的事件资源。函数首先检查 `obj` 是否小于 `OS_RESOURCE_MAX`，通过检查后进入中断关闭状态，调用 `os_res_init(&OS_RES[obj])` 初始化对应的统一资源对象，随后重新开启中断并返回成功。

```c
char result = os_event_init(0);

if (result == 1)
{
    /* 事件初始化成功 */
}
```

### 注意事项

- `obj` 必须小于 `OS_RESOURCE_MAX`。
- 初始化函数会调用统一资源初始化接口 `os_res_init()`。
- 资源对象各成员的具体初始化值，应以 `os_res_init()` 的实现为准。
- 初始化操作涉及中断状态修改，使用时应结合系统中断管理规则评估调用环境。

## 事件触发 os_event_write

### 函数原型

```c
char os_event_write(u8 obj);
```

### 参数说明

| 参数 | 类型 | 说明 |
|---|---|---|
| `obj` | `u8` | 事件资源槽位编号 |

### 返回值

| 返回值 | 说明 |
|---|---|
| `1` | 事件触发操作完成 |
| `-1` | 事件资源槽位编号无效 |

### 功能说明

触发指定事件，并遍历等待位图，尝试唤醒等待该事件的任务。

函数执行过程如下：

- 检查事件资源槽位编号是否合法。
- 将 `EA` 设置为 `0`。
- 将 `OS_RES[obj].value` 设置为 `1`，表示事件已触发。
- 当 `wait_cnt` 大于 `0` 时，遍历标准任务编号范围。
- 检查 `wait_mask` 中对应任务的位是否置位。
- 对位图中标记的任务调用 `wake_task(i, WAIT_SIGNAL)`。
- 将 `EA` 设置为 `1`，然后返回成功。

```c
char result = os_event_write(0);

if (result == 1)
{
    /* 事件触发操作完成 */
}
```

### 事件触发与状态保持

事件触发后，`value` 被设置为 `1`。根据当前实现，`os_event_write()` 本身不会在触发后自动将该值恢复为 `0`。

因此，事件状态具有保持特征：即使某个任务在事件触发之后才调用 `os_event_wait()`，只要事件状态仍为 `1`，该任务也会直接返回，不进入等待流程。

事件触发后，函数会遍历等待位图并对标记的任务调用唤醒接口。实际成功唤醒的任务数量及其后续调度行为，取决于 `wake_task()` 的具体实现和当时的任务状态。

### 中断与并发注意事项

当前实现通过直接操作 `EA` 控制中断状态，而不是通过临界区封装宏完成保护。

需要特别注意：

- 函数退出时直接执行 `EA = 1`，并非恢复进入函数前保存的中断使能状态。
- 从中断服务程序调用时，应结合具体中断嵌套规则和内核中断管理机制评估安全性。
- 从任务上下文调用时，也应评估与其他中断及内核操作之间的并发关系。
- 不能仅根据函数注释中的 ISR-safe 描述，就认定该接口在所有中断上下文中都安全。

在确认临界区和中断退出机制之前，不应将该函数描述为无条件安全的中断调用接口。

## 事件等待 os_event_wait

### 函数原型

```c
char os_event_wait(u8 obj, u16 tick);
```

### 参数说明

| 参数 | 类型 | 说明 |
|---|---|---|
| `obj` | `u8` | 事件资源槽位编号 |
| `tick` | `u16` | 最大等待时间参数，以系统节拍为单位 |

### 返回值

| 返回值 | 说明 |
|---|---|
| `1` | 调用时事件已经触发，函数直接返回 |
| `-1` | 事件资源槽位编号无效 |
| 其他返回值 | 由统一等待接口 `os_wait()` 返回 |

### 功能说明

等待指定事件触发。函数先检查事件资源槽位编号，再短暂关闭中断并检查事件状态。

当 `OS_RES[obj].value` 非零时，函数重新开启中断并直接返回 `1`，不进入等待状态。

当事件尚未触发时，函数重新开启中断，然后调用：

```c
return os_wait(WAIT_EVENT, obj, tick);
```

由统一等待接口处理后续的阻塞、超时和唤醒流程。

```c
char result = os_event_wait(0, 100);

if (result == 1)
{
    /* 调用时事件已经触发 */
}
else if (result == -1)
{
    /* 事件资源槽位编号无效 */
}
else
{
    /* 根据统一等待接口的返回规则处理 */
}
```

### 等待行为

事件等待接口包含两条不同的执行路径：

- **事件已触发：** 直接返回 `1`，不进入任务等待流程。
- **事件未触发：** 调用 `os_wait()`，进入统一的事件等待流程。

在等待过程中，事件触发可能通过 `wake_task()` 唤醒任务；等待超时则由统一等待机制处理。

`tick == 0` 是否表示无限等待，以及超时唤醒和事件唤醒分别返回什么结果，需要结合 `os_wait()` 和任务等待管理源码确认，不能仅凭本函数定义确定。

### 注意事项

- 该函数可能使当前任务进入阻塞状态。
- 等待时间以系统节拍为单位，而不是直接以毫秒为单位。
- 事件触发状态保持为 `1` 时，后续调用可以直接返回。
- 调用方应根据统一等待接口的实际返回约定处理超时和其他结果。

## 事件状态查询 os_event_query

### 函数原型

```c
char os_event_query(u8 obj);
```

### 参数说明

| 参数 | 类型 | 说明 |
|---|---|---|
| `obj` | `u8` | 事件资源槽位编号 |

### 返回值

| 返回值 | 说明 |
|---|---|
| `1` | 事件已触发 |
| `0` | 事件未触发 |
| `-1` | 事件资源槽位编号无效 |

### 功能说明

查询指定事件当前的触发状态。

函数先检查 `obj` 是否有效，然后读取对应资源对象的 `value` 字段：非零时返回 `1`，否则返回 `0`。

```c
char state = os_event_query(0);

if (state == 1)
{
    /* 事件已触发 */
}
else if (state == 0)
{
    /* 事件未触发 */
}
else
{
    /* 事件资源槽位编号无效 */
}
```

### 注意事项

- 该函数不主动修改事件状态。
- 该函数不会主动调用任务唤醒接口。
- 返回值为 `0` 时，只能说明读取时事件状态为零。
- 查询操作本身不代表事件状态在函数返回后仍然保持不变。

## 事件删除 os_event_delete

### 函数原型

```c
char os_event_delete(u8 obj);
```

### 参数说明

| 参数 | 类型 | 说明 |
|---|---|---|
| `obj` | `u8` | 事件资源槽位编号 |

### 返回值

| 返回值 | 说明 |
|---|---|
| `1` | 清除操作完成 |
| `-1` | 事件资源槽位编号无效 |

### 功能说明

当前实现检查资源槽位编号后，将指定资源对象的 `value` 字段设置为 `0`。

```c
char result = os_event_delete(0);

if (result == 1)
{
    /* 事件状态清除操作完成 */
}
```

需要注意，当前实现并没有调用资源释放函数，也没有主动清空 `wait_mask`、`wait_cnt` 或唤醒等待任务。因此，该函数实际执行的是清除事件状态，而不是完整销毁资源对象。

### 注意事项

- 调用后，事件状态被设置为未触发。
- 等待队列成员不会由本函数主动清理。
- 本函数不会主动唤醒等待任务。
- 不应将其描述为释放资源或清空等待队列的完整删除操作。

如果应用需要真正销毁事件对象，必须结合统一资源管理机制设计相应流程，避免残留等待状态影响后续使用。

## 使用流程

事件模块的典型使用流程是先初始化事件，再由任务等待事件，由事件产生方触发事件，最后根据需要查询或清除事件状态。

```c
/* 初始化事件 */
os_event_init(0);

/* 等待事件，最多等待指定的系统节拍数 */
char result = os_event_wait(0, 100);

/* 由事件产生方触发事件 */
os_event_write(0);

/* 查询事件状态 */
char state = os_event_query(0);

/* 清除事件触发状态 */
os_event_delete(0);
```

以上代码仅用于说明接口调用关系。实际多任务程序中，应由适当的任务或中断处理路径执行相应操作，并根据函数返回值进行错误处理。


## 使用说明

- **资源编号**：事件对象使用统一资源数组中的资源槽位，使用前应确保事件编号有效，并符合系统资源配置要求。
- **事件状态**：当前实现采用保持型事件状态。事件触发后，状态不会自动消费，具体状态变化应遵循事件接口的定义。
- **事件触发**：触发事件时，系统会处理等待该事件的任务，并通过统一任务唤醒机制通知符合条件的等待任务。
- **等待与超时**：事件等待的唤醒结果和超时行为由统一等待机制协同管理，调用时应遵循相应接口的返回值约定。
- **初始化与删除**：事件初始化和删除应遵循接口规定的生命周期管理方式。删除事件前，应确保不存在仍依赖该事件的任务或其他操作。
- **中断上下文**：事件接口的中断调用限制取决于具体实现。除非接口明确保证，否则不应默认其可在中断服务程序或嵌套中断环境中安全调用。
