# 邮箱模块

## 模块简介

邮箱模块提供基于统一资源模型的单字节消息传递机制，可用于任务间的数据传递、简单事件通知和任务同步。

邮箱使用 `OS_RES` 数组中的资源槽位存储数据，并通过等待任务位图记录等待该邮箱的任务。模块提供邮箱初始化、数据发送、数据接收、状态查询和内容清除等接口。

当前实现属于**单槽位邮箱**：每个邮箱资源只能保存一个字节的数据，不具备消息队列的缓存能力。发送新数据时，邮箱中的原有数据可能被覆盖。

## 设计目标

- 提供轻量级的单字节消息传递机制。
- 复用 HRTOS 统一资源结构，减少独立资源管理开销。
- 支持任务等待与发送后的等待任务唤醒。
- 提供阻塞接收和非阻塞查询两种访问方式。

## 使用场景

- 任务之间传递简单数据。
- 任务之间进行事件通知。
- 保存单个待处理消息。
- 配合任务等待机制实现基本同步。

## 数据类型

本模块使用 `hrtos_internal.h` 中定义的 `OS_RESOURCE` 结构，并通过 `OS_RES[mid]` 访问对应资源。

主要使用的成员如下：

| 成员 | 功能 |
|---|---|
| `value` | 保存邮箱数据，当前实现同时使用 `0` 表示空邮箱 |
| `owner` | 资源所有者字段，邮箱初始化时设置为 `OS_INVALID_ID` |
| `wait_mask` | 等待该资源的任务位图 |
| `wait_cnt` | 等待任务计数，初始化时清零 |

**重要限制：** 当前实现使用 `value == 0` 判断邮箱为空，因此不能可靠地区分“邮箱为空”和“邮箱中存放了 `0x00`”。如果需要传递完整的 `0x00`～`0xFF` 数据范围，应考虑增加独立的邮箱有效标志，或调整邮箱状态表示方式。

## 宏定义

本模块没有在公开头文件中定义专用宏。

邮箱编号的有效范围为：

`0 <= mid < OS_RESOURCE_MAX`

其中 `OS_RESOURCE_MAX` 表示系统资源槽位数量。

## API 函数列表

| 函数名称 | 功能说明 |
|---|---|
| `os_mailbox_init()` | 初始化邮箱资源 |
| `os_mailbox_send()` | 向邮箱写入数据并尝试唤醒等待任务 |
| `os_mailbox_receive()` | 接收邮箱数据，邮箱为空时尝试进入等待 |
| `os_mailbox_query()` | 查询邮箱当前保存的值 |
| `os_mailbox_clear()` | 清除邮箱当前保存的值 |

## API 详细说明

### os_mailbox_init

函数原型：

```c
void os_mailbox_init(u8 mid);
```

参数说明：

| 参数 | 类型 | 说明 |
|---|---|---|
| `mid` | `u8` | 邮箱对应的资源槽位编号 |

返回值：

无。

功能说明：

初始化指定邮箱资源。传入的编号超出 `OS_RESOURCE_MAX` 时，函数直接返回，不执行初始化。

初始化过程包括：

- 将 `value` 设置为 `0`。
- 将 `owner` 设置为 `OS_INVALID_ID`。
- 将 `wait_mask` 清零。
- 将 `wait_cnt` 清零。

调用示例：

```c
os_mailbox_init(0);
```

注意事项：

- `mid` 必须小于 `OS_RESOURCE_MAX`。
- 应在系统启动阶段或能够确保资源未被并发使用的环境中完成初始化。
- 初始化会清空等待位图及等待计数，不应在邮箱正在使用时随意调用。
- 初始化后，邮箱的 `value` 为 `0`，当前实现将其视为空状态。

### os_mailbox_send

函数原型：

```c
char os_mailbox_send(u8 mid, u8 content);
```

参数说明：

| 参数 | 类型 | 说明 |
|---|---|---|
| `mid` | `u8` | 邮箱对应的资源槽位编号 |
| `content` | `u8` | 待写入邮箱的数据 |

返回值：

| 返回值 | 说明 |
|---|---|
| `1` | 邮箱写入操作完成 |
| `-1` | 邮箱编号无效 |

功能说明：

向指定邮箱写入一个字节的数据。函数先关闭总中断，再将 `content` 写入邮箱的 `value` 字段。

如果 `wait_mask` 非零，函数从任务位图中查找第一个置位的任务编号，并调用 `wake_task(next, WAIT_SIGNAL)` 尝试唤醒该任务。随后恢复总中断并返回 `1`。

如果没有等待任务，则保留写入的数据，恢复总中断并返回 `1`。

调用示例：

```c
char result;

result = os_mailbox_send(0, 0x55);

if (result == 1)
{
    /* 邮箱写入操作完成 */
}
```

注意事项：

- 邮箱只有一个数据存储槽位，发送新数据会直接覆盖旧数据。
- 返回 `1` 代表函数完成了写入及相应的唤醒处理流程，并不代表接收任务已经成功处理数据。
- 当前实现没有检查邮箱中是否已有未接收的数据。
- 发送内容为 `0` 时，接收接口会将邮箱判断为空，因此 `0x00` 不能作为普通有效消息可靠传递。
- 函数通过直接设置 `EA = 0` 和 `EA = 1` 控制总中断，未保存并恢复调用前的中断使能状态。调用前若总中断原本关闭，函数返回前仍会将其打开。
- 当前提供的实现没有专门的 ISR 发送接口，不能据此认定该 API 可在任意中断上下文中安全调用。

### os_mailbox_receive

函数原型：

```c
int os_mailbox_receive(u8 mid);
```

参数说明：

| 参数 | 类型 | 说明 |
|---|---|---|
| `mid` | `u8` | 邮箱对应的资源槽位编号 |

返回值：

| 返回值 | 说明 |
|---|---|
| `-1` | 邮箱编号无效 |
| 其他值 | 函数返回的邮箱数据或等待后的读取结果，具体行为受当前实现及等待机制影响 |

功能说明：

从指定邮箱读取数据。邮箱编号无效时，函数直接返回 `-1`。

函数关闭总中断后检查邮箱的 `value`：

- 当 `value == 0` 时，先恢复总中断，再调用 `os_wait(WAIT_MAILBOX, mid, 0)`，尝试进入指定邮箱的等待流程。
- 当 `value != 0` 时，将数据复制到局部变量 `_data`，清空邮箱内容，恢复总中断并返回读取的数据。

在调用 `os_wait()` 后，当前实现会继续检查 `m->value`。如果此时 `value != 0`，函数返回局部读取路径中的数据；如果仍为 `0`，函数最终返回当前的 `m->value`。

调用示例：

```c
int data;

data = os_mailbox_receive(0);

if (data >= 0)
{
    /* 根据实际协议处理数据 */
}
```

注意事项：

- 邮箱有非零数据时，读取后会清空邮箱。
- 邮箱为空时，函数会尝试调用 `os_wait()`，但能否正确阻塞、唤醒并取得数据，需要结合 `os_wait()`、`wake_task()` 和调度器的实现验证。
- 当前代码没有在 `os_wait()` 返回后明确检查唤醒结果，也没有在该路径中重新执行与快路径相同的完整取数及清空操作。
- 当等待返回后邮箱仍为空时，函数会返回 `0`，而不是明确的等待失败状态。
- 由于 `0` 同时表示空邮箱，返回值无法可靠地区分有效的零值数据与空状态。
- 当前实现的接收慢路径存在需要进一步审查的地方，文档不应直接承诺“阻塞接收一定能够返回正确数据”。

### os_mailbox_query

函数原型：

```c
int os_mailbox_query(u8 mid);
```

参数说明：

| 参数 | 类型 | 说明 |
|---|---|---|
| `mid` | `u8` | 邮箱对应的资源槽位编号 |

返回值：

| 返回值 | 说明 |
|---|---|
| `-1` | 邮箱编号无效 |
| 其他值 | 当前 `value` 字段的值 |

功能说明：

读取指定邮箱的当前 `value`，不清除邮箱内容，也不主动调用等待或唤醒接口。

调用示例：

```c
int data;

data = os_mailbox_query(0);

if (data > 0)
{
    /* 当前邮箱保存了非零值 */
}
```

注意事项：

- 查询操作本身不修改邮箱状态。
- 返回 `0` 不能证明邮箱中存在一个有效的零值消息；按照当前实现，`0` 同时表示空状态。
- 该函数直接读取共享资源成员，没有显式关闭总中断或采用其他同步措施。并发访问时的可见性和一致性应结合具体调用环境评估。

### os_mailbox_clear

函数原型：

```c
char os_mailbox_clear(u8 mid);
```

参数说明：

| 参数 | 类型 | 说明 |
|---|---|---|
| `mid` | `u8` | 邮箱对应的资源槽位编号 |

返回值：

| 返回值 | 说明 |
|---|---|
| `1` | 清除操作完成 |
| `-1` | 邮箱编号无效 |

功能说明：

清除指定邮箱当前保存的值。编号有效时，函数关闭总中断，将 `OS_RES[mid].value` 设置为 `0`，随后重新打开总中断并返回 `1`。

调用示例：

```c
char result;

result = os_mailbox_clear(0);
```

注意事项：

- 清除操作会丢弃当前保存的数据。
- 该函数只修改 `value`，不会清除 `wait_mask`、`wait_cnt` 或修改 `owner`。
- 当前实现没有主动唤醒等待任务。
- 函数使用直接设置 `EA = 0`、`EA = 1` 的方式控制总中断，未恢复调用前的中断使能状态。

## 使用建议

- 邮箱适合保存单个待处理数据，不适合需要缓存多条消息的场景。
- 如果发送方可能连续发送多条消息，应评估覆盖风险，必要时使用消息队列等机制。
- 当前邮箱实现不适合可靠传递 `0x00`，在修正空状态表示之前，应明确限制消息数据范围。
- 在将邮箱用于关键任务同步前，应结合等待、唤醒和调度器源码验证完整的阻塞与唤醒流程。
- 在任务或中断上下文中调用相关接口时，应确认其执行上下文要求，以及总中断使能状态的处理方式。


## 使用说明

- **单消息存储**：邮箱用于保存单条消息，不提供多消息队列或消息缓存功能。连续发送消息时，新消息可能覆盖尚未接收的旧消息。
- **消息值限制**：当前实现使用 `value == 0` 表示邮箱为空，因此不应将零值作为需要可靠传递的有效消息。
- **发送与接收**：发送和接收操作通过统一资源管理及任务等待机制协同工作。使用时应遵循接口规定的调用顺序，并正确处理返回结果。
- **等待与唤醒**：邮箱操作可能涉及等待任务的唤醒，具体行为取决于统一等待与任务调度机制。
- **初始化时机**：初始化会重置邮箱状态及相关等待信息。应在邮箱尚未投入使用时完成初始化，避免影响正在等待或使用该邮箱的任务。
- **并发访问**：多个任务共享邮箱时，应遵循系统的任务调度与同步约定，不应默认查询、发送和清空操作具备完整的并发保护。
- **中断状态**：使用邮箱接口时，应注意其对中断使能状态的影响；在中断服务程序或临界区中调用前，应确认接口符合相应的调用约束。
