# 消息队列模块

## 模块简介

消息队列模块提供基于环形缓冲区的单字节消息传递机制，支持消息缓存、阻塞收发和非阻塞收发。

消息队列通过 `os_msgq_t` 控制块管理缓冲区地址、队列容量、读写索引及当前消息数量。发送操作将数据写入队列，接收操作从队列中读取数据。队列已满或为空时，可根据调用参数选择立即返回或调用内核等待接口。

与单槽位邮箱相比，消息队列可以缓存多条消息，适合生产者与消费者之间存在处理速度差异的场景。

## 设计目标

- 提供轻量级的任务间消息传递机制。
- 使用环形缓冲区缓存多条单字节消息。
- 支持阻塞与非阻塞两种收发模式。
- 通过统一资源模型中的等待位图和任务唤醒机制协调收发任务。

## 使用场景

- 任务间传递字节数据。
- 缓存传感器采样结果或串口接收数据。
- 解耦数据生产任务与数据处理任务。
- 缓冲突发消息，平滑生产与消费速度差异。

## 数据类型

### os_msgq_t

消息队列控制块类型为 `os_msgq_t`。当前实现使用以下成员：

| 成员 | 功能说明 |
|---|---|
| `buf` | 环形缓冲区首地址 |
| `_size` | 缓冲区容量，即可保存的消息数量上限 |
| `head` | 写入索引 |
| `tail` | 读取索引 |
| `count` | 当前队列中的消息数量 |

`head` 和 `tail` 均以 `_size` 为模循环递增。`count` 用于区分队列为空和队列已满的状态，因此该实现可以使用全部 `_size` 个缓冲区字节，不需要额外保留一个空槽位。

## 宏定义

本模块没有在公开头文件中定义专用宏。

## API 函数列表

| 函数名称 | 功能说明 |
|---|---|
| `os_msgq_init()` | 初始化消息队列并绑定缓冲区 |
| `os_msgq_send()` | 向消息队列发送一个字节 |
| `os_msgq_recv()` | 从消息队列接收一个字节 |
| `os_msgq_clear()` | 清空队列状态 |

## API 详细说明

### os_msgq_init

函数原型：

```c
void os_msgq_init(os_msgq_t *q, u8 *buf, u8 _size);
```

参数说明：

| 参数 | 类型 | 说明 |
|---|---|---|
| `q` | `os_msgq_t *` | 消息队列控制块指针 |
| `buf` | `u8 *` | 用户提供的环形缓冲区地址 |
| `_size` | `u8` | 队列容量，单位为字节消息数 |

返回值：

无。

功能说明：

将消息队列控制块与指定缓冲区关联，并初始化队列状态：

- `q->buf = buf`：保存缓冲区地址。
- `q->_size = _size`：设置队列容量。
- `q->head = 0`：将写入索引复位。
- `q->tail = 0`：将读取索引复位。
- `q->count = 0`：将消息数量清零。

调用示例：

```c
u8 msg_buffer[16];
os_msgq_t my_queue;

os_msgq_init(&my_queue, msg_buffer, sizeof(msg_buffer));
```

注意事项：

- `q` 和 `buf` 必须指向有效内存。
- 缓冲区实际容量必须不小于 `_size`。
- 当前实现没有检查空指针，也没有检查 `_size` 是否为零。
- `_size` 为零时，收发路径中的取模运算可能产生错误，因此必须传入非零容量。
- 初始化会重置控制块状态，不应在队列仍被其他任务使用时随意重新初始化。
- 初始化只设置控制块，不会清除缓冲区中原有的字节内容；这些内容在 `count` 清零后不属于有效消息。

### os_msgq_send

函数原型：

```c
char os_msgq_send(os_msgq_t *q, u8 obj, u8 _data, char nonblock);
```

参数说明：

| 参数 | 类型 | 说明 |
|---|---|---|
| `q` | `os_msgq_t *` | 消息队列控制块指针 |
| `obj` | `u8` | 用于等待与唤醒管理的资源对象编号 |
| `_data` | `u8` | 待发送的单字节数据 |
| `nonblock` | `char` | 非零表示非阻塞模式，零表示阻塞模式 |

返回值：

| 返回值 | 说明 |
|---|---|
| `1` | 消息写入成功 |
| `0` | 非阻塞模式下队列已满 |
| 其他值 | 阻塞路径中 `os_wait()` 返回的结果 |

功能说明：

向指定消息队列写入一个字节的数据。函数通过 `q->count` 判断队列是否已满。

**队列未满时**

- 将 `_data` 写入 `q->buf[q->head]`。
- 更新写入索引：`q->head = (q->head + 1) % q->_size`。
- 将消息数量加一。
- 检查 `OS_RES[obj].wait_mask`，查找等待该对象且等待类型为 `WAIT_MSG_RECV` 的任务。
- 找到任务后，调用 `wake_task(next, WAIT_SIGNAL)` 尝试唤醒。
- 恢复总中断并返回 `1`。

**队列已满时**

- 非阻塞模式：恢复总中断并返回 `0`。
- 阻塞模式：恢复总中断后调用 `os_wait(WAIT_MSG_SEND, obj, 0)`，并将等待接口的返回值保存在局部变量中。
- 如果等待返回后队列出现可用空间，函数继续执行写入流程；如果队列仍然已满，则返回等待接口的结果。

调用示例：

```c
u8 msg_buffer[16];
os_msgq_t my_queue;
char result;

os_msgq_init(&my_queue, msg_buffer, sizeof(msg_buffer));

/* 非阻塞发送 */
result = os_msgq_send(&my_queue, 0, 0x55, 1);

if (result == 1)
{
    /* 消息已写入队列 */
}
```

注意事项：

- `obj` 不仅是普通参数，还用于访问 `OS_RES[obj]` 并管理等待任务。必须确保该编号有效，并与对应消息队列的等待管理约定一致。
- 当前函数没有验证 `q`、`q->buf` 或 `obj` 的有效性。
- 队列满时，阻塞模式能否正确恢复执行并完成发送，取决于 `os_wait()`、`wake_task()` 和调度器的实现。
- 该函数通过直接设置 `EA = 0` 和 `EA = 1` 控制总中断，没有保存并恢复调用前的中断使能状态。
- 当前提供的源码没有定义专用的 `os_msgq_send_from_isr()` 接口，因此不应将该函数描述为具有独立的 ISR 安全版本。

### os_msgq_recv

函数原型：

```c
char os_msgq_recv(os_msgq_t *q, u8 obj, u8 *_data, char nonblock);
```

参数说明：

| 参数 | 类型 | 说明 |
|---|---|---|
| `q` | `os_msgq_t *` | 消息队列控制块指针 |
| `obj` | `u8` | 用于等待与唤醒管理的资源对象编号 |
| `_data` | `u8 *` | 接收数据的存储地址 |
| `nonblock` | `char` | 非零表示非阻塞模式，零表示阻塞模式 |

返回值：

| 返回值 | 说明 |
|---|---|
| `1` | 消息读取成功 |
| `0` | 非阻塞模式下队列为空 |
| 其他值 | 阻塞路径中 `os_wait()` 返回的结果 |

功能说明：

从消息队列中读取一个字节的数据。函数通过 `q->count` 判断队列是否为空。

**队列非空时**

- 从 `q->buf[q->tail]` 读取队头消息，并写入 `*_data`。
- 更新读取索引：`q->tail = (q->tail + 1) % q->_size`。
- 将消息数量减一。
- 检查 `OS_RES[obj].wait_mask`，查找等待该对象且等待类型为 `WAIT_MSG_SEND` 的任务。
- 找到任务后，调用 `wake_task(next, WAIT_SIGNAL)` 尝试唤醒。
- 恢复总中断并返回 `1`。

**队列为空时**

- 非阻塞模式：恢复总中断并返回 `0`。
- 阻塞模式：恢复总中断后调用 `os_wait(WAIT_MSG_RECV, obj, 0)`，并保存等待接口的返回值。
- 如果等待返回后队列中已有消息，函数继续执行读取流程；如果队列仍为空，则返回等待接口的结果。

调用示例：

```c
u8 msg_buffer[16];
os_msgq_t my_queue;
u8 data;
char result;

os_msgq_init(&my_queue, msg_buffer, sizeof(msg_buffer));

/* 非阻塞接收 */
result = os_msgq_recv(&my_queue, 0, &data, 1);

if (result == 1)
{
    /* data 为接收到的消息 */
}
```

注意事项：

- `_data` 必须指向可写内存，当前实现没有检查该指针是否有效。
- `obj` 必须与该消息队列的等待管理约定一致。
- 当前阻塞路径将 `os_wait()` 的返回值保存在局部变量中；只有等待返回后队列仍有消息时，才会进入实际读取分支。
- 当前函数没有在读取前显式验证 `obj < OS_RESOURCE_MAX`。
- 函数通过直接设置 `EA = 0` 和 `EA = 1` 控制总中断，没有恢复调用前的中断使能状态。
- 当前提供的源码没有定义专用的 `os_msgq_recv_from_isr()` 接口，不应据此承诺该函数可安全用于任意中断上下文。

### os_msgq_clear

函数原型：

```c
void os_msgq_clear(os_msgq_t *q);
```

参数说明：

| 参数 | 类型 | 说明 |
|---|---|---|
| `q` | `os_msgq_t *` | 消息队列控制块指针 |

返回值：

无。

功能说明：

将消息队列的运行状态复位：

- `q->head = 0`。
- `q->tail = 0`。
- `q->count = 0`。

调用示例：

```c
os_msgq_clear(&my_queue);
```

注意事项：

- 清空后，队列中的所有未读取消息均被视为无效。
- 函数只修改控制块，不擦除缓冲区内存中的实际字节。
- 当前实现不会主动唤醒等待发送或等待接收的任务。
- 函数没有检查 `q` 是否为空指针。
- 函数通过直接设置 `EA = 0` 和 `EA = 1` 控制总中断，没有恢复调用前的中断使能状态。

## 使用建议

- 根据最大突发消息量和消费者处理速度选择缓冲区容量。
- 在调用初始化接口前，为控制块和缓冲区分配足够且生命周期稳定的内存。
- 不要使用零容量队列。
- 多任务并发访问同一个队列时，应保证等待对象编号、资源等待位图与队列实例之间的对应关系正确。
- 对实时性要求较高的路径，可根据业务特点使用非阻塞模式，避免任务因队列状态进入等待。
- 若需要在中断中传递数据，应确认内核提供的专用中断安全接口及其调用约束；不要直接假定普通收发函数适用于 ISR。


## 使用说明

- **初始化配置**：初始化消息队列时，应确保控制块和缓冲区指针有效，并设置符合实际存储空间的队列容量。
- **资源编号**：发送和接收操作应使用有效的队列资源编号，并遵循项目中消息队列接口的定义。
- **队列容量**：消息队列的存储能力受配置容量限制。使用时应根据生产者与消费者的处理速度合理设置容量，并正确处理发送或接收操作的返回结果。
- **阻塞与等待**：阻塞式收发依赖统一等待、任务唤醒和调度机制。调用时应遵循接口规定的等待条件与返回值约定。
- **清空操作**：清空操作用于重置队列中的消息状态，不应默认其会自动取消或唤醒正在等待的任务。执行前应确认队列及相关任务处于适当状态。
- **并发访问**：多个任务共享消息队列时，应结合系统调度和同步机制设计收发流程，避免未经协调的并发操作影响队列状态。
- **中断上下文**：除非接口明确保证，否则不要默认消息队列接口适用于中断服务程序或嵌套中断环境。
