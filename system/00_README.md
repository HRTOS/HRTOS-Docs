# HRTOS 系统手册

## 概述

HRTOS（Hard Real-Time Operating System）是一款面向 8051 系列微控制器的实时操作系统，围绕任务调度、上下文切换、中断处理、任务同步和系统资源管理构建内核。

HRTOS 采用标准任务与高速任务相结合的任务模型，提供任务管理、优先级调度、时间片机制、统一 IPC 资源管理、消息队列、邮箱、定时服务及中断相关机制。内核结合 8051 的寄存器组、堆栈和数据存储体系进行设计，在有限的硬件资源下提供完整的任务管理与系统运行支持。

本手册面向 HRTOS 内核开发者与维护者，系统介绍内核架构、核心机制、模块实现、内部数据结构、系统运行流程、调试方法及性能测试，为内核研究、代码维护、功能扩展和平台移植提供技术依据。

应用开发、模块调用及 API 使用方法，请参考 HRTOS 用户开发文档、API 文档、模块使用手册与示例工程。

## 文档结构

本手册按照内核架构、核心机制、系统运行和工程维护组织，主要包括以下内容：

- **内核架构：** 内核模块划分、工程目录结构、核心数据结构及模块依赖关系。
- **调度与任务管理：** 调度器设计、任务模型、任务状态、任务创建及上下文切换。
- **IPC 与资源管理：** 事件、信号量、互斥锁、消息队列、邮箱及统一等待与唤醒机制。
- **时间与中断：** 系统时基、任务延时、中断处理、临界区保护及调度请求。
- **内存与平台移植：** DATA、IDATA、XDATA、任务栈、寄存器组及目标芯片适配。
- **系统运行流程：** 内核启动、任务注册、调度执行、等待与唤醒等关键流程。
- **内核维护与扩展：** 模块维护、功能扩展、问题定位及修改验证。
- **调试与性能测试：** 任务切换、中断响应、定时精度、内存占用及相关测试结果。

各专题围绕具体模块展开，共同构成 HRTOS 内核的设计与维护文档体系。

## 系统特性

| 项目 | 说明 |
|---|---|
| 目标平台 | 8051 系列微控制器 |
| 主要开发环境 | Keil C51 |
| 任务模型 | 标准任务与高速任务 |
| 调度机制 | 基于优先级的任务调度，支持相应的抢占式调度与时间片机制 |
| 时间管理 | 基于 Timer0 的系统时基及相关时间服务 |
| 任务管理 | 任务创建、删除、挂起、恢复、退出及状态维护 |
| IPC 机制 | 事件、消息队列、信号量、互斥锁与邮箱 |
| 等待机制 | 统一等待状态管理、任务唤醒及超时处理 |
| 中断机制 | 中断上下文管理、临界区保护及调度请求 |
| 资源管理 | 静态配置、统一资源状态管理及任务注册控制 |

HRTOS 将任务调度、IPC、时间管理和中断处理组织为相互协作的内核模块，为 8051 应用提供统一的系统运行基础。

## 快速参考

### 核心数据结构

| 名称 | 用途 |
|---|---|
| `OS_TCB` | 保存标准任务的优先级、状态和等待信息 |
| `OS_RESOURCE` | 统一资源对象，保存资源状态及等待任务相关信息 |
| `os_msgq_t` | 消息队列控制结构，管理缓冲区、读写位置及消息数量 |
| 调度器状态变量 | 记录当前任务、调度状态及相关调度控制信息 |

### 核心配置

| 配置项 | 当前配置值 | 用途 |
|---|---:|---|
| `OS_PROCESS_MAX` | `16` | 标准任务数量配置 |
| `OS_FAST_TASK_MAX` | `2` | 高速任务数量配置 |
| `OS_RESOURCE_MAX` | `6` | 统一资源对象数量 |
| `OS_MSGQ_MAX` | `3` | 消息队列对象数量 |
| `OS_SCHED_LEVEL_MAX` | `10` | 调度级别上限定义 |

普通任务使用 0–7 级优先级，高速任务对应第 8 级，中断相关执行级别为 9 和 10。

### 内存布局

HRTOS 根据 8051 的内部数据存储区、扩展数据存储区和任务栈组织内核数据。以下为一组典型配置中的内存区域示例：

| 内存区域 | 地址范围 | 用途 |
|---|---|---|
| 系统栈区域 | `0x35–0x39` | 系统相关栈空间 |
| 中断栈区域 | `0x3A–0x41` | 中断处理相关栈空间 |
| 用户栈区域 | `0x42–0x7F` | 用户任务相关栈空间 |
| XDATA 全局区域 | `0x0200–0x03FF` | 扩展数据存储区中的全局数据区域 |

上述地址对应特定的内存配置，不代表所有 8051 芯片的通用内存布局。实际使用时，应结合目标芯片的 RAM 容量、寄存器区划分、编译器存储分配和 HRTOS 移植配置进行规划。

## 系统要求

### 硬件要求

HRTOS 面向 8051 系列微控制器。进行芯片选型和工程移植时，需要重点考虑以下资源：

- **指令集与执行机制：** 支持目标内核所需的 8051 指令及相关硬件机制。
- **内部 RAM：** 满足内核变量、任务栈、寄存器保存及其他运行时数据的空间需求。
- **XDATA：** 满足统一资源对象、任务控制信息及其他扩展数据的存储需求。
- **程序存储器：** 满足内核、驱动和应用程序的代码空间需求。
- **定时器与中断：** 提供系统时基及应用运行所需的中断资源。

最低资源要求与实际可用任务数量、功能配置及应用规模有关。选型时应结合目标芯片的数据手册、内核配置和编译结果评估。

### 开发环境

- **Keil C51：** HRTOS 的主要开发环境。
- **目标芯片工具链：** 用于完成芯片配置、程序编译、下载和调试。
- **硬件测试环境：** 用于验证任务调度、中断响应、时间精度、内存使用及系统稳定性。

### 移植与构建

移植 HRTOS 时，需要根据目标芯片调整相关硬件配置，确认定时器与中断设置、存储区域分配及任务栈布局，并完成编译、链接和目标硬件测试。

修改任务数量、资源数量、时间参数或内存配置后，应重新检查编译结果、存储空间占用及系统运行表现。
