# HRTOS 内核概述

## 模块介绍

HRTOS（Hard Real-Time Operating System）是一款面向 8051 系列微控制器的实时操作系统，围绕任务调度、上下文切换、中断处理、任务同步及系统资源管理构建内核。

内核采用标准任务与高速任务相结合的任务模型，提供任务管理、统一 IPC 资源管理、消息队列、邮箱、定时服务、事件同步及中断相关机制。通过静态配置管理核心任务与资源对象，并利用统一等待模型组织任务阻塞与唤醒，适配 8051 有限的存储资源和处理能力。

本文档面向内核开发者与维护者，介绍 HRTOS 的源码组织、核心配置、数据结构、任务状态、等待机制、内核对象、核心函数及主要运行流程，为源码阅读、系统调试、功能扩展和平台维护提供参考。

## 主要职责

HRTOS 内核主要负责以下工作：

- **任务管理：** 创建、删除、挂起、恢复、退出及任务状态维护。
- **任务调度：** 根据任务优先级和调度模式选择执行任务，支持相应的抢占式调度与时间片机制。
- **上下文切换：** 保存和恢复任务执行环境，实现任务之间的执行权切换。
- **统一 IPC 管理：** 通过统一资源对象组织相关资源状态，支持信号量、互斥锁、事件等同步机制。
- **消息队列与邮箱：** 管理消息缓冲区、读写位置、消息数量及消息收发操作。
- **统一等待机制：** 记录任务等待类型、等待对象、等待结果及超时相关信息。
- **任务唤醒：** 根据资源状态、信号及超时条件更新任务状态，使符合运行条件的任务重新参与调度。
- **定时服务：** 提供系统时基、任务延时、Tick 查询及时间转换功能。
- **中断管理：** 提供中断状态查询、中断 ID 获取、临界区保护及调度请求接口。
- **运行时维护：** 管理空闲任务、任务退出及相关清理操作。
- **任务注册控制：** 控制是否允许继续注册新任务，并提供任务优先级查询与设置接口。

## 核心配置

核心配置集中定义在 `config.h` 中，包括基础类型、时间参数、任务数量、调度级别、任务状态、等待类型及资源对象容量。

### 基础类型

```c
#define u8  unsigned char
#define u16 unsigned int
#define f32 float
#define u32 unsigned long
#define f64 double
#define NULL 0
```

这些类型定义用于统一内核代码中的基础类型名称。在 Keil C51 环境中，变量的实际存储位置还受到 `data`、`idata`、`xdata` 等存储类型限定的影响。

### 时间配置

```c
#define OS_TIME_ONCE_DEFAULT 5
#define OS_TIME_T0 10000
```

- `OS_TIME_ONCE_DEFAULT`：默认时间片相关配置，当前值为 `5`。
- `OS_TIME_T0`：系统定时相关配置，当前值为 `10000`。

时间片配置与系统定时配置承担不同职责。系统实际时基和调度周期由相应的定时器配置与内核处理逻辑共同决定。

### 任务数量配置

```c
#define OS_PROCESS_MAX 16
#define OS_FAST_TASK_MAX 2
#define OS_MAX_TASK OS_PROCESS_MAX
```

- `OS_PROCESS_MAX`：标准任务数量配置，值为 `16`。
- `OS_FAST_TASK_MAX`：高速任务数量配置，值为 `2`。
- `OS_MAX_TASK`：`OS_PROCESS_MAX` 的别名。

标准任务和高速任务采用不同的任务管理与调度处理方式。标准任务控制块数组的容量由 `OS_PROCESS_MAX` 决定，高速任务则由专门的高速任务机制管理。

### 调度级别

```c
#define OS_SCHED_LEVEL_MAX 10
```

调度级别定义如下：

| 级别 | 含义 |
|---|---|
| 0–7 | 普通任务优先级 |
| 8 | 高速任务级别 |
| 9 | 中断级 |
| 10 | 中断嵌套级 |

普通任务优先级用于任务调度；中断级别用于描述中断相关的执行层级。中断级别 `9` 和 `10` 不属于普通任务优先级的设置范围。

### IPC 资源数量

```c
#define OS_RESOURCE_MAX 6
#define OS_MSGQ_MAX 3
```

- `OS_RESOURCE_MAX`：统一资源对象数组容量，值为 `6`。
- `OS_MSGQ_MAX`：消息队列对象数组容量，值为 `3`。

事件、信号量、互斥锁等使用统一资源模型的对象通过资源对象管理相关状态。邮箱和消息队列具有各自的对象组织方式。

## 核心数据结构

### OS_TCB：任务控制块

`OS_TCB` 用于保存标准任务的优先级、运行状态和等待状态等信息。

```c
typedef struct {
    u8 base_prio;
    u8 cur_prio;
    u8 state;
    u8 wait_type;
    u8 wait_flag;
    u8 wait_obj;
    u16 wait_tick;
} OS_TCB;
```

字段说明：

| 字段 | 含义 |
|---|---|
| `base_prio` | 任务基础优先级 |
| `cur_prio` | 当前生效的任务优先级 |
| `state` | 任务状态 |
| `wait_type` | 当前等待类型 |
| `wait_flag` | 等待结果标志 |
| `wait_obj` | 当前等待对象 ID |
| `wait_tick` | 等待超时相关 Tick 计数 |

`OS_TCB` 不包含独立的 `id` 字段。任务 ID 通过任务管理中的索引规则与任务控制块对应。

### OS_RESOURCE：统一资源对象

```c
typedef struct {
    u8 value;
    u8 owner;
    u8 wait_cnt;
    u16 wait_mask;
    u8 pending_signal;
} OS_RESOURCE;
```

字段说明：

| 字段 | 含义 |
|---|---|
| `value` | 资源相关状态值 |
| `owner` | 资源拥有者信息，主要用于需要记录所有者的资源类型 |
| `wait_cnt` | 等待任务数量相关计数 |
| `wait_mask` | 等待任务位图 |
| `pending_signal` | ISR 相关的待处理信号计数 |

`wait_mask` 是一个 16 位位图，用于表示标准任务的等待情况：

- bit0 对应 task0。
- bit1 对应 task1。
- 依此类推，bit15 对应 task15。

统一资源对象集中保存资源状态与等待任务信息，为 IPC 模块复用底层等待和唤醒逻辑提供支持。不同 IPC 类型根据自身功能使用相应字段。

### os_msgq_t：消息队列控制结构

```c
typedef struct {
    u8 *buf;
    u8 _size;
    u8 head;
    u8 tail;
    u8 count;
} os_msgq_t;
```

字段说明：

| 字段 | 含义 |
|---|---|
| `buf` | 消息缓冲区指针 |
| `_size` | 缓冲区容量 |
| `head` | 写指针，对应生产者 |
| `tail` | 读指针，对应消费者 |
| `count` | 当前消息数量 |

消息队列使用缓冲区和读写位置组织消息，并通过 `count` 记录当前队列中的消息数量。发送与接收操作需要同步维护读写位置和消息计数，并处理队列的边界状态。

## 核心内核对象

### 任务控制块数组

```c
extern OS_TCB xdata OS_TASK[OS_PROCESS_MAX];
```

`OS_TASK` 保存标准任务的控制信息，数组容量由 `OS_PROCESS_MAX` 决定。当前配置支持最多 16 个标准任务控制块。

高速任务采用专门的管理与上下文处理机制，不应直接将 `OS_TASK` 的容量视为高速任务数量。

### 统一资源对象数组

```c
extern xdata OS_RESOURCE OS_RES[OS_RESOURCE_MAX];
```

`OS_RES` 保存统一资源对象，容量由 `OS_RESOURCE_MAX` 决定。当前配置支持 6 个统一资源对象。

资源对象的初始化和分配由资源初始化及对应 IPC 模块共同管理。

### 消息队列对象数组

```c
extern xdata os_msgq_t OS_MSGQ[OS_MSGQ_MAX];
```

`OS_MSGQ` 保存消息队列控制结构，容量由 `OS_MSGQ_MAX` 决定。当前配置支持 3 个消息队列对象。

每个队列通过自身的缓冲区指针、容量、读写位置和消息数量管理队列数据。

## 任务状态与等待机制

### 任务状态

```c
#define READY    0
#define WAIT     1
#define RUNNING  2
#define SUSPEND  3
#define DEAD     4
```

| 状态 | 数值 | 含义 |
|---|---:|---|
| `READY` | 0 | 就绪态，具备运行条件 |
| `WAIT` | 1 | 等待某种条件或资源 |
| `RUNNING` | 2 | 正在运行 |
| `SUSPEND` | 3 | 挂起态 |
| `DEAD` | 4 | 任务结束或删除后的状态 |

任务状态用于描述任务在内核中的运行阶段。任务管理模块负责执行状态变更，调度器根据任务状态判断任务是否具备运行条件。

### 等待类型

```c
#define WAIT_NONE      0
#define WAIT_DELAY     1
#define WAIT_SEM       2
#define WAIT_MUTEX     3
#define WAIT_MSG_SEND  4
#define WAIT_MSG_RECV  5
#define WAIT_EVENT     6
#define WAIT_MAILBOX   7
```

| 类型 | 数值 | 含义 |
|---|---:|---|
| `WAIT_NONE` | 0 | 无等待 |
| `WAIT_DELAY` | 1 | 延时等待 |
| `WAIT_SEM` | 2 | 信号量等待 |
| `WAIT_MUTEX` | 3 | 互斥锁等待 |
| `WAIT_MSG_SEND` | 4 | 消息队列发送等待 |
| `WAIT_MSG_RECV` | 5 | 消息队列接收等待 |
| `WAIT_EVENT` | 6 | 事件等待 |
| `WAIT_MAILBOX` | 7 | 邮箱等待 |

等待类型与 `wait_obj` 配合，标识任务当前等待的资源类别及具体对象。消息队列发送等待和接收等待分别描述发送方向和接收方向的阻塞场景。

内核通过任务控制块中的等待字段和资源对象中的等待记录维护等待关系。任务等待状态发生变化时，相关等待信息需要保持一致。

### 唤醒标志

```c
#define WAIT_TIMEOUT 1
#define WAIT_SIGNAL  2
```

- `WAIT_TIMEOUT`：超时唤醒标志。
- `WAIT_SIGNAL`：信号唤醒标志。

唤醒标志用于区分任务结束等待的原因。统一等待与唤醒机制负责维护相应的等待结果。

### 统一等待模型

统一等待机制通过任务控制块中的等待字段和资源对象中的等待信息协同工作。

基本处理流程如下：

1. 等待接口确定等待类型及等待对象。
2. 内核更新任务控制块中的等待信息。
3. 对需要登记资源等待信息的操作，更新对应资源的等待记录。
4. 任务进入等待状态，并在必要时触发调度。
5. 资源满足条件或等待超时后，执行相应唤醒处理。
6. 唤醒逻辑更新任务状态和等待结果，任务重新参与调度。

事件、信号量、互斥锁、邮箱和消息队列通过统一等待机制协调任务阻塞与唤醒，同时保留各自的资源操作语义。

```text
    ↓
底层启动与初始化
    ↓
进入内核启动流程
    ↓
初始化任务及资源相关结构
    ↓
调用用户初始化入口 hrtos_main()
    ↓
创建并注册应用任务
    ↓
完成启动阶段配置
    ↓
启用相应中断及调度机制
    ↓
进入正常运行阶段
```

系统启动由底层启动代码、内核初始化、用户初始化和任务调度等环节共同完成。应用在初始化阶段创建并注册任务，内核随后进入正常调度运行阶段。

### 任务创建流程

```text
os_task_create(...)
    ↓
检查创建参数
    ↓
检查任务 ID 与相关资源限制
    ↓
分配或定位任务栈
    ↓
初始化任务上下文
    ↓
设置任务控制信息
    ↓
完成任务注册
    ↓
返回执行结果
```

任务创建过程负责完成参数检查、任务资源准备、上下文初始化及任务注册，使新任务具备参与调度的条件。

### 等待与唤醒流程

```text
调用等待接口
    ↓
确定等待类型与对象
    ↓
记录任务等待信息
    ↓
更新相关资源等待状态
    ↓
任务进入等待状态
    ↓
请求必要的调度
    ↓
资源满足条件或等待超时
    ↓
执行唤醒处理
    ↓
任务重新参与调度
```

等待接口负责建立任务与等待对象之间的关联；唤醒处理负责更新任务状态和等待结果。任务重新具备运行条件后，由调度器根据调度规则选择执行任务。

## 设计原则

### 内存效率

- 使用静态配置管理核心任务与资源对象。
- 采用紧凑的数据结构控制内核管理信息的存储开销。
- 通过任务栈管理机制组织任务执行所需的栈空间。
- 使用 DATA、IDATA 和 XDATA 等 8051 存储区域组织内核数据。

### 实时调度

- 根据任务优先级和调度模式执行任务选择。
- 支持相应的任务抢占与时间片机制。
- 通过专门的上下文切换逻辑管理任务执行环境。
- 提供中断相关接口、临界区保护及调度请求机制。

调度延迟、上下文切换时间和中断响应时间应结合目标芯片、编译配置、任务负载和实测结果进行评估。

### 8051 平台适配

- 根据目标芯片的数据存储体系组织变量。
- 结合寄存器组、堆栈和中断机制管理任务执行上下文。
- 针对目标编译环境实现关键路径。
- 根据芯片资源和编译结果检查内存布局。

### 统一 IPC 模型

- 使用 `OS_RESOURCE` 统一组织相关资源状态。
- 通过 `OS_TCB` 保存任务等待信息。
- 使用等待类型、等待对象和等待位图协同管理任务阻塞与唤醒。
- 在复用底层等待机制的同时，保留不同 IPC 类型的行为语义。

### 任务注册控制与优先级管理分离

- 通过任务注册控制接口管理是否允许继续注册新任务。
- 通过优先级接口查询和设置任务优先级。
- 将任务注册权限与任务运行优先级作为两类独立功能管理。

## 系统约束

当前核心配置如下：

| 项目 | 当前配置 |
|---|---|
| 标准任务数量配置 | `OS_PROCESS_MAX = 16` |
| 高速任务数量配置 | `OS_FAST_TASK_MAX = 2` |
| 统一资源对象数量 | `OS_RESOURCE_MAX = 6` |
| 消息队列对象数量 | `OS_MSGQ_MAX = 3` |
| 普通任务优先级范围 | 0–7 |
| 高速任务级别 | 8 |
| 中断相关调度级别 | 9–10 |
| 任务状态 | `READY`、`WAIT`、`RUNNING`、`SUSPEND`、`DEAD` |
| 等待类型 | `WAIT_NONE` 至 `WAIT_MAILBOX` |

内核使用固定容量的标准任务控制块数组、统一资源对象数组和消息队列对象数组。调整任务数量、资源数量、优先级或内存相关配置时，需要同步检查相关数据结构、调度逻辑、编译结果和目标硬件运行表现。

任务等待字段、资源等待记录及任务状态之间需要保持一致。任务注册控制、任务优先级管理和任务调度分别承担不同职责，不应混淆。

## 内核维护与调试

维护 HRTOS 内核时，可按照问题类型定位对应模块：

- **调度问题：** 检查任务优先级、调度模式、任务状态及调度请求路径。
- **任务阻塞：** 检查等待类型、等待对象、等待标志及唤醒条件。
- **IPC 问题：** 检查资源对象状态、等待位图和等待计数的一致性。
- **中断问题：** 检查中断上下文、临界区保护及调度触发逻辑。
- **消息队列问题：** 检查缓冲区容量、读写位置、消息计数及边界处理。
- **内存问题：** 检查任务栈以及 DATA、IDATA 和 XDATA 的分配与使用情况。
- **任务注册问题：** 检查任务注册锁定状态、任务创建时机及注册接口的调用顺序。
- **实时性能问题：** 在明确测试条件的前提下测量调度延迟、上下文切换时间和中断响应时间。

内核修改应保持接口定义、任务状态、等待关系及资源管理规则的一致性，并通过功能测试和目标硬件测试验证修改结果。

本概述用于建立 HRTOS 内核的整体认知。进一步研究具体功能时，可结合对应源文件、内部头文件、API 文档及专项设计说明，深入分析模块实现与调用关系。
