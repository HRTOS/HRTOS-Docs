# HRTOS 目录分析

## 模块介绍

HRTOS 是一款面向 8051 系列微控制器的实时操作系统。工程采用模块化源码组织方式，将公共接口、内核实现、任务管理、进程间通信（IPC）、定时服务、中断处理及平台相关代码分别组织，形成职责清晰的系统结构。

本文档介绍 HRTOS 的头文件目录、源代码目录、主要模块职责及模块间的调用关系，为开发者理解内核结构、阅读源码和进行系统维护提供参考。

## 主要职责

HRTOS 的目录结构主要承担以下职责：

- **接口与实现分离：** 通过头文件组织接口声明，通过源文件实现具体功能。
- **功能模块划分：** 按内核、任务、IPC、定时和中断等功能组织源码。
- **统一等待与唤醒：** 通过统一等待机制管理任务阻塞、等待状态及任务唤醒。
- **平台适配：** 集中组织处理器相关的底层实现。
- **任务管理：** 提供任务创建、注册、状态管理、挂起、恢复和删除等功能。
- **应用开发支持：** 通过公共头文件提供应用程序所需的系统接口。

## Inc/ 目录：头文件

`Inc/` 目录包含系统公共接口、配置定义、核心数据结构及内核内部声明。

### 文件清单

| 文件 | 主要职责 |
|---|---|
| `hrtos.h` | 公共 API 汇总入口 |
| `config.h` | 系统配置、类型定义、状态常量及核心数据结构 |
| `hrtos_internal.h` | 内核内部声明及实现相关定义 |
| `kernel.h` | 内核初始化与核心接口 |
| `task.h` | 任务管理接口 |
| `event.h` | 事件同步接口 |
| `interrupt.h` | 中断处理与临界区接口 |
| `mutex.h` | 互斥锁接口 |
| `semaphore.h` | 信号量接口 |
| `time.h` | 时间管理与延时接口 |
| `wait.h` | 统一等待机制接口 |
| `mailbox.h` | 邮箱接口 |
| `msgq.h` | 消息队列接口 |

### 目录特点

- 通过头文件声明函数、数据类型及相关配置。
- 通过 `config.h` 统一定义内核配置、基础类型、状态常量和核心数据结构。
- 通过 `hrtos.h` 为应用程序提供统一的头文件入口。
- 通过各功能头文件组织任务管理、事件同步、中断处理、资源同步、时间服务及 IPC 接口。
- 通过 `hrtos_internal.h` 组织内核内部使用的声明和实现相关定义。

## Src/ 目录：源代码实现

`Src/` 目录按照内核功能划分源码，各子目录分别实现对应的系统功能。

| 文件 | 主要职责 |

| `scheduler.c` | 调度器选择与调度模式处理 |
| `scheduler_dispatch.c` | 任务分发处理 |
| `scheduler_mode.c` | 调度模式相关处理 |
| `task_create.c` | 任务创建与注册 |
| `task_cleanup.c` | 任务清理与相关资源处理 |

| `os_data.c` | DATA 存储区相关处理 |
| `os_xdata.c` | XDATA 存储区相关处理 |

**主要职责**

- 组织内核核心数据与调度状态。
- 实现调度器选择及任务分发。
- 负责任务创建与注册。
- 处理任务清理及相关资源。

- 组织 DATA、XDATA 存储区相关实现。

该目录包含任务注册控制和任务优先级管理两类功能。

**任务注册控制**

| 文件 | 主要职责 |

| 文件 | 主要职责 |
|---|---|
| `task_get_priority.c` | 获取任务优先级 |

任务注册控制用于管理系统是否允许继续注册新任务；任务优先级接口用于查询或设置任务优先级。两类功能职责独立，不应将任务注册锁定描述为优先级锁定。

## 核心函数与接口组织

### 公共头文件入口

应用程序通过 `Inc/hrtos.h` 使用 HRTOS 公共接口：

```c
#include "hrtos.h"
```

`hrtos.h` 汇总应用开发所需的相关头文件，使应用程序能够通过统一入口访问系统接口。`config.h` 提供系统配置、基础类型及核心数据结构定义，其他功能头文件分别组织对应模块的 API。

### 内核启动与任务调度

HRTOS 的启动和运行涉及内核初始化、任务创建与注册、系统时钟、中断处理及任务调度等功能。

主要功能环节包括：

- **内核数据准备：** 初始化内核运行所需的数据与状态。
- **任务创建与注册：** 建立任务及其相关调度信息。
- **资源与同步对象初始化：** 初始化应用使用的资源及 IPC 对象。
- **时钟与中断处理：** 提供系统时基和相关中断处理。
- **调度与任务执行：** 根据调度条件选择任务并执行上下文切换。
- **等待与唤醒：** 在任务阻塞条件满足后恢复任务运行资格。

### 统一等待与 IPC 的协作

事件、互斥锁、信号量、邮箱和消息队列各自提供独立的操作接口，并通过统一等待与唤醒机制协调任务阻塞和恢复。

- **事件：** 提供事件状态设置、查询与等待。
- **互斥锁：** 提供共享资源访问的互斥控制。
- **信号量：** 提供任务同步与通知。
- **邮箱：** 提供邮箱消息发送与接收。
- **消息队列：** 提供队列消息发送与接收。
- **统一等待：** 管理相关等待条件与任务唤醒。
- **调度器：** 在调度条件满足时选择后续运行任务。

## 模块间调用关系

HRTOS 各模块按照功能职责协同工作，形成以下主要关系：

```text
任务管理
    ├── 核心内核与调度
    ├── 统一等待与唤醒
    └── 任务注册控制与优先级管理

事件模块 ─────┐
互斥锁模块 ───┤
信号量模块 ───┤
邮箱模块 ─────┼──→ 统一等待与唤醒
消息队列模块 ─┘

中断模块
    ├── ISR 事件操作
    ├── ISR 消息队列操作
    ├── ISR 邮箱操作
    ├── ISR 信号量操作
    └── 调度请求

定时模块
    └── 任务延时与时间相关处理

核心内核与调度
    ├── 任务选择与分发
    ├── 任务创建与注册
    └── 任务清理与空闲任务管理
```

### 头文件组织

公共头文件通过 `hrtos.h` 汇总，主要功能头文件包括：

```text
hrtos.h
    ├── config.h
    ├── kernel.h
    ├── task.h
    ├── event.h
    ├── interrupt.h
    ├── mutex.h
    ├── semaphore.h
    ├── time.h
    ├── wait.h
    ├── mailbox.h
    └── msgq.h
```

该结构体现了 HRTOS 公共接口按功能划分的组织方式，便于应用程序根据统一入口或具体功能头文件使用相应接口。

## 目录维护建议

- **接口变更：** 修改公共 API 时，同步维护函数声明、实现及接口文档。
- **配置变更：** 调整任务数量、资源数量或调度参数后，检查内存占用和运行行为。
- **等待机制变更：** 检查任务控制块中的等待信息、资源等待记录及唤醒路径。
- **中断接口变更：** 检查 ISR 上下文限制、临界区处理和调度请求逻辑。
- **任务注册控制变更：** 确保锁定与解锁行为符合任务注册阶段的设计约定。
- **平台相关变更：** 结合目标芯片、编译器及存储模型进行测试。
- **文档维护：** 保持目录说明、函数职责、API 文档与当前实现一致。

## 总结

HRTOS 采用模块化目录结构，将核心内核、任务管理、IPC、定时服务、中断处理及平台相关实现组织在不同模块中。

`Src/kernel/` 负责核心内核与调度相关功能，`Src/task/` 管理任务生命周期，`Src/wait/` 负责统一等待与唤醒，事件、互斥锁、信号量、邮箱和消息队列模块分别提供对应的同步与通信功能，`Src/interrupt/` 提供中断上下文相关操作，`Src/task_priority/` 则负责任务注册控制和优先级管理。

通过清晰的模块划分，HRTOS 将任务调度、同步通信、时间管理及中断相关操作组织为相互协作的内核功能，为源码阅读、系统维护和应用开发提供统一的工程结构。
