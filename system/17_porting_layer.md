# HRTOS 移植层

## 模块介绍

HRTOS 移植层用于封装与目标 MCU、硬件寄存器及编译环境相关的底层实现，减少硬件差异对上层模块的影响。

当前提供的移植代码主要面向 STC12C5A60S2 和 STC8H8U64K，已实现串口初始化及 RAM 区字符串输出。串口初始化负责配置串口工作模式、波特率发生器及相关中断控制，字符串输出接口用于向串口发送以 `\0` 结尾的字符串。

需要注意，串口移植代码只是 HRTOS 整体硬件适配的一部分。系统时基、任务调度、中断管理、上下文切换和内存布局等功能，仍需结合内核实现、目标芯片和编译环境进行配置与验证，不能仅凭串口移植代码判断其完整移植状态。

## 当前支持的平台

| 目标平台 | 已实现功能 | 主要硬件差异 |
|---|---|---|
| STC12C5A60S2 | 串口初始化、RAM 区字符串输出 | 使用 Timer1 模式 2 产生波特率，采用 12T 配置方式下常见的定时器设置 |
| STC8H8U64K | 串口初始化、RAM 区字符串输出 | 通过 AUXR 配置 Timer1 为 1T 计数，并选择 Timer1 作为串口波特率发生器 |

具体波特率取决于系统时钟、定时器时钟、重载值及芯片的串口分频配置。移植时应以目标芯片的数据手册和实际测量结果为准。

## 主要接口

### `bsp_uart_init()`

初始化串口及其波特率发生器。

当前两个平台均将串口配置为模式 1，即 8 位 UART、可变波特率，并通过 Timer1 提供波特率时钟。两个平台的定时器配置存在差异，不能直接互换初始化代码。

STC12C5A60S2 的主要配置：

- 将 Timer1 设置为模式 2，即 8 位自动重装模式。
- 将 `TH1` 和 `TL1` 设置为 `0xFD`。
- 禁止 Timer1 中断并启动 Timer1。
- 设置 `EA = 1`、`ES = 1`。

STC8H8U64K 的主要配置：

- 通过 `AUXR` 将 Timer1 配置为 1T 计数模式。
- 通过 `AUXR` 选择串口 1 使用 Timer1 作为波特率发生器。
- 将 `TH1` 设置为 `0xFE`、`TL1` 设置为 `0xE0`。
- 禁止 Timer1 中断并启动 Timer1。
- 设置 `ES = 0`。

STC8H8U64K 的代码没有显式设置 `EA`，也没有在初始化函数中配置 `TMOD` 的 Timer1 工作模式。因此，相关寄存器的最终状态还可能受启动代码及此前的硬件初始化影响。若后续要将该实现作为独立、可复用的 BSP，建议结合芯片手册确认这些配置是否完整。

### `bsp_uart_send_str_ram(const char *s)`

发送位于 RAM 区的字符串，直到遇到字符串结束符 `\0`。

接口实现采用轮询方式发送每个字节：

- 将当前字符写入 `SBUF`。
- 等待发送完成标志 `TI` 置位。
- 清除 `TI`，继续发送下一个字符。
- 遇到 `\0` 后结束发送。

该接口为阻塞式输出。发送期间，调用任务或函数需要等待串口完成当前字符串的发送，因此不适合直接用于要求严格执行时间上限的路径。尤其应避免在不允许阻塞的中断服务程序中调用。

调用方应传入有效的、以 `\0` 结尾的 RAM 字符串指针。该接口没有提供空指针检查，也没有实现超时退出机制；如果发送完成标志无法正常置位，函数可能一直等待。

## 串口配置差异

### STC12C5A60S2

```c
SCON = 0x50;

TMOD &= 0x0F;
TMOD |= 0x20;

TL1 = 0xFD;
TH1 = 0xFD;

ET1 = 0;
TR1 = 1;

EA = 1;
ES = 1;
```

该配置将 Timer1 设置为模式 2，并使用 `0xFD` 作为自动重装值。实际波特率仍取决于系统时钟及芯片的定时器、串口时钟配置。

### STC8H8U64K

```c
SCON = 0x50;

TMOD &= 0x0F;

AUXR |= 0x40;
AUXR &= 0xFE;

TL1 = 0xE0;
TH1 = 0xFE;

ET1 = 0;
TR1 = 1;

ES = 0;
```

该配置通过 `AUXR` 设置 Timer1 的 1T 计数方式，并选择 Timer1 作为串口 1 的波特率发生器。由于代码没有显式设置 Timer1 的 `TMOD` 模式位，实际工作模式应结合 STC8H8U64K 的寄存器定义和初始化环境确认。

两个平台的寄存器配置服务于各自的硬件环境。新增芯片时，应单独确认串口模式、波特率时钟来源、定时器工作模式、中断控制及相关寄存器的复位状态，不应只替换定时器重载值。

## 移植层与内核的边界

移植层负责处理目标硬件与运行环境相关的差异；内核负责任务管理、调度、等待与唤醒、IPC 等操作系统机制。

当前提供的串口代码不实现以下功能：

- Timer0 系统时基及系统 Tick 管理。
- 任务调度与上下文切换。
- 任务栈布局和寄存器现场保存。
- 内核临界区及通用中断管理。
- 内存分配、任务资源和 IPC 管理。

上述功能属于 HRTOS 整体运行机制的一部分，其实现可能涉及其他内核源文件、配置文件或特定编译器约定。移植到新平台时，应以对应版本的实际源码为依据，明确哪些功能已经实现、哪些功能需要调整。

## 新平台适配要点

### 硬件与编译环境

确认目标 MCU 的 8051 内核实现、系统时钟、定时器时钟方式、RAM 与 XDATA 容量，以及编译器对特殊功能寄存器和中断函数的支持情况。

### 串口适配

根据目标芯片重新确认串口工作模式、波特率发生器、定时器模式、重载值和中断控制方式，并验证实际通信波特率。

如果目标平台采用不同的寄存器布局或专用波特率发生器，应为其提供独立的硬件适配实现，避免直接复用不兼容的寄存器配置。

### 内核适配

核对系统时基、中断入口、临界区、上下文切换、任务栈与内存布局等实现。上述内容必须与实际内核代码及目标编译环境保持一致，不能仅通过串口输出正常来判定内核已经完成移植。

### 功能验证

完成硬件配置后，应分别验证串口输出、系统启动、任务调度、延时、IPC、中断响应和长时间运行稳定性。串口输出测试只能证明相应的串口路径可以工作，不能替代内核功能验证。

## 当前限制

- 当前展示的串口移植实现面向 STC12C5A60S2 和 STC8H8U64K。
- 串口字符串输出采用轮询方式，属于阻塞式接口。
- 当前接口仅提供 RAM 区字符串输出，没有展示代码存储区字符串输出或通用串口收发接口。
- 当前提供的代码不足以证明所有 8051 系列 MCU 均可直接移植。
- 不同芯片的时钟体系、寄存器定义、内存资源和编译器约定可能存在差异，需要分别验证。

## 总结

HRTOS 当前提供的移植代码主要用于 STC12C5A60S2 和 STC8H8U64K 平台的串口初始化与 RAM 区字符串输出。两个平台通过不同的 Timer1 和 AUXR 配置实现串口波特率发生，体现了硬件相关代码需要按目标芯片分别适配的特点。

进行新平台移植时，应以实际源码和芯片手册为依据，区分串口等外设适配与内核运行机制适配，并通过实际硬件测试确认功能和时序表现。保持硬件差异与内核机制之间的边界清晰，有助于后续维护、扩展和问题定位。
