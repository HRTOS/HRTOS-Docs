# HRTOS 调试指南

## 模块介绍

本指南用于帮助开发者定位 HRTOS 系统运行过程中遇到的问题，包括任务运行异常、调度异常、时间精度问题、中断问题以及资源同步问题。

调试过程应遵循：

- 从简单现象入手
- 使用可测量的方法定位问题
- 避免引入额外影响系统实时性的调试代码
- 修改后进行充分验证

## 调试工具

### 串口输出调试

#### 目的

通过串口输出关键运行信息，辅助分析系统状态。

#### 适用场景

- 任务创建结果检查
- 状态变量观察
- 参数配置确认
- 错误定位

#### 注意事项

串口输出会增加系统执行时间，可能影响实时性能。

在实时性敏感代码中，应避免大量打印。

建议：

- 调试阶段使用
- 测试完成后关闭或减少输出

### 逻辑分析仪

#### 目的

分析 HRTOS 运行时序，验证实时性能。

#### 可测量内容

- 任务切换时间
- 中断响应时间
- 时间片周期
- 延时精度
- GPIO 时序变化

#### 使用方法

通过 GPIO 输出标志信号：

```c
GPIO = 1;

// 执行需要测量的代码

GPIO = 0;
```

使用逻辑分析仪观察高低电平持续时间，即可获得执行时间。

## 任务调试

### 任务未运行

#### 常见现象

- 任务创建成功但没有执行
- 其他任务运行正常
- 系统没有明显错误

#### 检查步骤

- 检查任务创建结果
- 检查任务状态
- 检查任务优先级
- 检查任务阻塞条件

- 等待任务状态

## 中断调试

### 中断未响应

检查：

- 中断是否开启
- 中断入口是否正确
- 中断源配置是否正确
- ISR 是否正常退出

### ISR 注意事项

ISR 中应：

- 保持执行时间短
- 避免阻塞
- 使用 ISR 安全 API
- 不直接执行复杂任务操作

HRTOS 中断处理流程：

```text
硬件中断
    ↓
进入 ISR
    ↓
执行 ISR 安全 API
    ↓
更新内核状态
    ↓
设置调度请求
    ↓
退出中断
    ↓
内核检查调度请求
    ↓
必要时执行任务切换
```

## 栈调试

### 栈溢出问题

常见现象：

- 系统异常复位
- 变量异常变化
- 任务运行不稳定

检查：

- 任务栈空间
- 函数调用深度
- 局部变量使用
- 中断嵌套情况

## IPC 调试

### 信号量问题

检查：

- 信号量是否正确创建
- 等待任务是否能够唤醒
- 释放操作是否执行

### 互斥锁问题

检查：

- 是否正确释放锁
- 是否存在资源竞争
- 是否长时间占用资源

### 消息通信问题

检查：

- 消息发送状态
- 接收任务状态
- 消息缓冲区状态

## 常见问题排查

| 问题 | 可能原因 | 检查方向 |
|-|-|-|
| 系统无响应 | 中断异常、调度停止 | 检查 Timer0、中断状态 |
| 任务不运行 | 创建失败、阻塞等待 | 检查任务状态 |
| 调度异常 | 时间配置错误 | 检查调度触发 |
| 栈溢出 | 栈空间不足 | 检查栈使用 |
| 中断异常 | ISR 配置错误 | 检查中断入口 |
| IPC 无响应 | 资源状态异常 | 检查同步对象 |

## 调试最佳实践

### 分阶段验证

建议：

- 单任务运行
- 多任务调度
- 增加 IPC
- 增加中断
- 长时间运行测试

### 保持测试可重复

记录：

- 硬件环境
- 编译配置
- 测试程序
- 测试时间

### 修改后回归测试

每次修改内核后：

- 重新编译
- 执行基础测试
- 执行长时间运行测试

确保系统稳定。

## 总结

HRTOS 调试应以实际运行数据为依据，通过串口、逻辑分析仪和硬件测试手段定位问题。

由于实时系统对时间敏感，调试过程中应尽量减少对系统运行环境的影响，优先采用低侵入性的测试方法。
